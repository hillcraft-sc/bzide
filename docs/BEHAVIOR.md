# Behavior spec

How the app behaves, written so the web and Android clients can be ported from this file rather than from the Swift code. Each playback rule gets a manual checklist entry for testing on a real device.

## Server communication

- Protocol: Subsonic API 1.16.1 as implemented by Navidrome, JSON (`f=json`), HTTP GET.
- Requests go to `<base URL>/rest/<endpoint>`. Any path in the base URL is kept, so servers behind a reverse proxy subpath work.
- Only `http` and `https` base URLs are accepted.
- Auth: every request carries `u`, `t = md5(password + salt)`, `s = salt`, `v`, `c` (the client name, `Bzide`). The salt is 16 random bytes as hex, new for every request. The plain password is never sent.
- Query values are percent-encoded including `+`, because the server decodes a bare `+` as a space.
- **API keys** (OpenSubsonic `apiKeyAuthentication`): Sign In offers **Password** or **API Key**. With a key, every request carries `apiKey` instead of `u`, `t` and `s` (the spec forbids sending both), no password is stored, and the username comes from the server (`tokenInfo`, which also checks the key; error 44 is an invalid key). Codes 40 to 44 count as authentication failures; 41 (token sign-in not supported for the account) suggests an API key.
- **Plain http warning:** Sign In warns, under the address, when it's `http://` to an address outside this network or a private one, as the username and token (or key) can then be read on the way. Local and private addresses aren't warned about: `localhost`, names without a dot, `.local`, `.lan`, `.home.arpa`, `.internal`, IPv4 10/8, 172.16/12, 192.168/16, 127/8, 169.254/16 and 100.64/10 (Tailscale and other VPNs), and IPv6 loopback, unique-local and link-local. It's a warning; signing in still works.
- **No disk cache:** every connection (the server and each outside service) uses a private session: no URL cache, cookies or stored credentials; background downloads keep no cache either. iOS's shared URL cache is emptied at each launch, as earlier versions left server answers there on disk, keyed by request URLs carrying the username and token.
- Auth parameters (`t`, `s`, `u`, `p`, `apiKey`) are replaced with `REDACTED` before a URL is logged.
- **Settings > Help** shows the user guide, `docs/USER-GUIDE.md`, the same way as Privacy (below): bundled, drawn natively, and also readable on the web wherever the file is hosted. Numbered steps show with their numbers.
- **Settings > Privacy** shows the privacy page, `docs/PRIVACY.md`, bundled with the app (the same file, so the two never differ) and drawn natively: headings, paragraphs, bullet lists, and its services table as a card per service (the first column as the title, the others labeled with their headers), with bold, italic and links styled.
- Errors are reported as one of: invalid base URL, network failure, non-2xx HTTP status, server `status: "failed"` (with the Subsonic error code), or an unreadable response. Codes 40 and 41 count as authentication failures.
- Decoding is tolerant, because servers fill fields inconsistently:
  - An item without a non-empty `id` is dropped. Nothing else in its list is affected.
  - Any other field that is missing, `null`, or the wrong type is treated as absent. Numbers sent as strings (`"320"`, `"187.0"`) and booleans sent as strings are accepted. Missing names and titles become empty strings; the UI chooses a placeholder.
  - A list sent as a single object is treated as a one-element list. A missing list is empty.
  - List endpoints (`getArtists`, `getAlbumList2`, `getPlaylists`, `getRandomSongs`, `search3`) return an empty result when the wrapper object is missing. Single-item endpoints (`getArtist`, `getAlbum`, `getPlaylist`) report an error. `getArtistInfo2` is the exception: a missing or empty `artistInfo2` means the server knows nothing more, not an error.
  - `starred` is read as "starred if present", ignoring the date.
  - `userRating` is 1–5 stars; 0, missing, or anything out of range means unrated.
- Media (`stream`, `download`, `getCoverArt`) is fetched by URL, not through the API client. These URLs contain a valid token, so they are built on demand and never logged or persisted.
- Scrobble times are sent in milliseconds since the Unix epoch. `submission=false` updates "now playing" only.
- OpenSubsonic: `getOpenSubsonicExtensions` returning a server error or HTTP 404 means "no extensions", not a failure. Network failures are still reported.

## Account

- One account (server address and user) is signed in at a time. Its login is in the Keychain only.
- Settings shows the user and the server's host name beside a profile picture (a person symbol unless a Gravatar is shown), and Sign Out (after confirmation).
- **Profile picture** (Settings > Profile > Picture): None (the default), Contact Card, Photo or Gravatar. A picture replaces the Settings gear on Library and shows at the top of Settings beside the user; with None, or a choice that has no picture yet, the gear stays (and Settings shows a person symbol). iOS gives apps no way to read the Apple Account photo, and on iPhone no way to know which contact is the user, so these are the closest options.
  - **Contact Card:** "Choose Contact Card…" opens Apple's contact picker (contacts without a photo can't be picked); only the picked contact's photo reaches the app, so no Contacts permission is asked. **Photo:** "Choose Photo…" opens Apple's photo picker; only the chosen photo reaches the app, no Photos permission. Either is cropped to a centered square, shrunk to 480 pixels and saved (`Application Support/ProfilePictures`, one per choice, so switching back keeps it). Later changes to the contact or photo don't carry over until it's picked again. An image that can't be read says so.
  - **Gravatar:** the email is the one typed in Profile, or, if that's empty, the one on the server account (`getUser`, asked only once Gravatar is chosen, once per session). The account email is remembered with the profile, so offline at launch the saved picture is still found; when the server answers, a changed email is followed, and a failed request leaves the remembered one in place. It's looked up as the SHA-256 of the trimmed, lowercased address (`https://gravatar.com/avatar/<hash>?s=240&d=404`), so the address itself is never sent; `d=404` means only a real picture counts, never a stand-in face. Typing waits 0.6 s after the last keystroke. Profile shows what happened: found (with the picture), no Gravatar for this email, the account has no email, not an email address, or Gravatar couldn't be reached. A picture, or "none for this email", is kept for a day in `Caches/Gravatar`, so it shows at once on launch and offline; when a lookup fails, the last picture stays. Requests use their own cookie-less session.
  - The choice and email (`Application Support/Profile.json`) and all saved pictures belong to the account and are kept for it like its settings (below): another user doesn't see them, and they come back when the account signs in again. The downloaded Gravatar picture is cached account data, fetched again. Settings saved by the first, Gravatar-only version carry over.
- Sign out pauses playback (saving the position), unloads the player, clears the lock screen and Control Center, tries once to send unsent scrobbles, and removes the login. It does not delete anything else.
- Downloads, the saved queue, unsent scrobbles, play history, cached cover art (and the cached Gravatar picture), the radio stations saved on this iPhone and their remembered logos belong to the account they came from. Signing back in to the same account keeps them all. When a different server or user signs in, before anything loads, the downloads, cached cover art and cached Gravatar picture (large, and fetched again from the server) are deleted, and everything else (the queue, play history, unsent scrobbles, saved stations and what's remembered about them, Spin the Dial's log, with the settings below) is set aside for the previous account and comes back when it signs in again. Nothing from one account (in particular, scrobbles) reaches another.
- **Before a switch, Sign In asks first** ("Sign In as a Different Account?"), once the server has accepted the login: it says how much the previous account's downloads take up and that its settings, history and queue are kept. **Same Server, Keep Everything** is for the same server reached at a different address (local network, domain, VPN), which counts as a different account otherwise: the new address takes over everything on the iPhone, downloads included, with no switch. **Sign In and Remove Downloads** switches. **Cancel** stays on the sign-in screen, nothing changed. Signing out and back in to the same account never asks.
- The owning account is recorded as a SHA-256 fingerprint of the server address and username, never in plain text. The same server written differently (letter case, trailing slash) is the same account; the username must match exactly. Data from before this check existed is assumed to belong to whoever signs in next.
- **Settings are kept per account**, not deleted: everything in Settings (streaming and download quality, playback options, the outside-service switches, theme and accent, how long history is kept, Wishlist removal…), the Library layout, the remembered filters and sorts (Search, Favorites, Radio), collapsed carousels, the visualizer's style and colors, lyrics timing fixes, the Wishlist, and the profile (picture choice, email and saved pictures). When a different account signs in, the outgoing account's settings are set aside on this iPhone (in `Application Support/AccountSettings/<fingerprint>/`, with its Wishlist and profile files), the settings are cleared, and the incoming account's are put back if it has signed in here before; otherwise it starts with the defaults (every outside service off). Screens already loaded (theme, Library layout, Settings) switch at once. Signing out, or back in to the same account, changes nothing. Only which account owns the data stays for the iPhone. Settings from before this existed belong to whoever signs in next.
- **Restore Default Settings** (at the end of Settings, after confirmation) puts the signed-in account's settings back to how Bzide starts: every setting (online services off), theme and accent, the Library layout, remembered filters and sorts, collapsed carousels and the visualizer's choices. It keeps the account's data (downloads, history, queue), how long history is kept and Show Every Play (so no plays are deleted), the Wishlist, the profile and lyrics timing fixes. Screens already open follow at once.
- CarPlay switches to "Sign in on your iPhone" on sign-out and back to the library on sign-in.

## Playback

- One engine owns the queue and playback state. The UI shows that state and sends commands; it never changes playback itself.
- Status is one of: idle (nothing queued), paused, buffering, playing, or failed (with a message).
- Gapless: the player always holds the current track and the one after it, so the next track is buffered before the current one ends. When a track ends, the player moves on by itself and the engine loads the track after that.
- Next uses the already-buffered next track. On the last track it does nothing.
- Previous, jump, and starting a new queue load the chosen track from the start, keeping the play/pause state.
- When the last track ends with repeat off, the queue is done: it is emptied, status becomes idle, and Now Playing (lock screen, Control Center) is cleared. If the player runs out while the queue still has a next track (it couldn't be loaded in time), playback carries on with that track instead.
- Seek is clamped to the track's length.
- Duration comes from the server's metadata until the player knows the real duration.
- Stream URLs contain auth tokens, so they are built only when a track is loaded and are never saved.
- On launch, a saved queue is restored paused at its saved position. Nothing loads or plays until the user presses play.
- The queue is saved whenever it changes. While playing, the position is saved every 10 seconds of playback, and on pause and seek.
- Failures are covered under "Network recovery" below. If a stream URL can't be built, the track fails without retrying.

### Audio session and interruptions

- The audio category (playback, long-form audio routing policy, which routes to AirPlay and CarPlay like other music apps) is set once at launch, while the session is inactive, and again after a media services reset, which forgets it. On every play the app then activates the session asynchronously (iOS 27's non-blocking activation, so the main thread never waits) and starts the player only once it's active; meanwhile the status is Buffering, and the player's own "paused" reports are ignored. Pausing, an interruption, media services going down, the queue ending or a new queue cancels a waiting activation, so a late one never starts playback; a skip to the preloaded next song keeps it, and that song starts when it completes. If the system refuses, the track shows as failed ("Can't play right now: …") and play tries again.
- When the system takes audio away (call, Siri, alarm, another app), playback pauses. If music was playing, the app remembers that.
- When the system later sends its resumption recommendation, playback resumes only if music was playing before the interruption **and** the system recommends resuming. A missing recommendation means don't resume.
- If the user presses play or pause during an interruption, their choice wins and the app won't auto-resume.
- When the output device goes away (headphones unplugged, Bluetooth disconnected, car turned off), playback pauses and stays paused. It never continues through the speaker, and reconnecting does not auto-resume by itself. Many cars send a play command by themselves when they reconnect (seen on device, 2026-10-11, and reported by a tester getting back in the car hours later, Gitea #27). iOS delivers it as an ordinary remote play, with nothing to say a person didn't press it, so: for 5 seconds after a CarPlay or Bluetooth audio output connects (the route changes to it with `newDeviceAvailable`, or the CarPlay screen connects, whichever comes first), a remote play, or play/pause while paused, is ignored and logged, unless Settings > CarPlay > **Play When CarPlay Connects** is on (off by default). Pause, next and previous always work, and so does anything chosen in the app or on CarPlay's lists; after the 5 seconds, play from the car, the Lock Screen or headphones works as usual. A person pressing play within those seconds isn't heard either and presses again. Wired headphones aren't covered: they don't send play on connect.
- When the system restarts its audio services ("media services were reset"), the app throws away its player and builds a new one. If music was playing (or buffering, or reconnecting), it reloads the current track at the same position and keeps playing; the user didn't stop it and the output route hasn't changed. If it was paused, it stays paused, and play picks up at the same position.
- Before a full audio reset the system first reports that media services were lost, and the audio system can stay down for many seconds (about 18 on device). During that outage the app shows paused, ignores the player's failure reports (they aren't real track failures), and doesn't retry anything. The tracks can fail a moment before the loss is announced; that failure starts reconnecting, which still counts as music on, so the resume still happens. While the outage lasts the app isn't playing, so iOS may suspend it and remove it from Control Center; it resumes once the reset arrives, which in practice can be when the user returns to the app. Pressing play during the outage shows reconnecting and starts once audio is back; pressing pause cancels the automatic resume. The queue is unchanged, Now Playing is sent again in full, and it counts as the same play for scrobbling.

### Audio levels (visualizer groundwork)

- The player can tap each item's audio (an `MTAudioProcessingTap` on its audio mix) to measure live left/right levels for a future visualizer. The tap passes the audio through untouched and its real-time callbacks never lock or allocate: they measure with vDSP and store numbers in atomics that the UI reads as it draws.
- Every item is tapped when it's loaded, before it plays (a streamed item once its audio track has loaded, normally while it buffers), and the tap stays until the item is gone. Adding or removing a tap on an item that's playing makes AVFoundation rebuild its audio chain, heard as a skip, so the tap is never added or removed mid-song. What's switched is only whether it measures: off by default and at every launch, on while the visualizer is open (or the Debug player's "Audio tap" switch is on). Not measuring, it just passes the audio through.
- Over AirPlay the tap sees no audio, so the levels stay still while playback itself is unaffected (confirmed on device 2026-10-12). AirPlay 2 sends the encoded audio to the receiver, which decodes and plays it; it never passes through the phone's local audio path where the tap sits. A visualizer needs a fallback while AirPlay is the output.
- Radio stations get no levels either (playback unaffected; confirmed on device 2026-10-12). A live stream reports no audio track up front, and even attaching the tap to the track the playing item exposes later (tried the same day) gives no audio: the tap is attached but never called. AVFoundation plays endless streams through a path that skips audio taps, so a visualizer needs the same fallback for radio as for AirPlay.

### Visualizer

- Now Playing's waveform button (in the row with the heart, rating and AirPlay) opens a full-screen visualizer on black, with a close button and a capsule naming the current style at the top, and the song's title and artist with previous, play/pause and next at the bottom (the same commands as Now Playing: previous off for radio, next only when there's a next song), so it needn't be closed to change track. Sideways (wider than tall), the title and controls move to a panel on the right, vertically centered, so the drawing gets the full height on the left; Plasma still fills the screen, darkened toward the panel instead of top and bottom. Two styles, changed by swiping left or right or from the capsule's menu: **Bars**, about 40 spectrum bars, bass on the left to treble on the right (60 Hz to 16 kHz, spaced like musical pitch); **Waveform**, the sound wave as a glowing line across the middle; and **Plasma**, the classic demoscene effect over the whole screen behind the controls (a Metal shader, `Plasma.metal`): four sine waves interfere into fine swirling bands that cycle through the palette twice, at steady brightness, darkened a little at the top and bottom so the controls stay readable. The music drives it without strobing: a **beat** signal jumps when the bass rises suddenly above its recent average (by 0.25 or more for a full beat; the average follows at 3/s) and fades at 5/s, and each beat zooms the pattern in slightly, sends a ripple through it, pushes the flow on and lifts the brightness by at most 10%. The flow is a clock that only moves forward, at 0.4 to 1.4 times its normal pace by mid-range energy plus the beat's push, so it never jumps. The bass swells the circular rings, the mid-range strengthens the diagonal bands, and the treble adds a fine shimmer and slides the colors along.
- **Polygraph**, after a lie detector: off-white chart paper fills the whole screen, running past four steel needles at 70 points a second, with the controls floating over it in dark ink instead of white (a black play button; the text and buttons get a soft halo of paper so the ink under them doesn't clutter them). In portrait the needles reach down from pivots above the top edge, their tips just below the menu, and the paper runs down; sideways they reach in from the left and the paper runs right, away from the controls panel. The grid (lines every 16 points, every fifth darker) covers the sheet and moves with the paper. Pens 1–3 follow the bass, mid-range and treble: each swings either way around its lane's center by how much its part is louder (or quieter) than it has been lately (its own average, following at 0.8/s; a change of 0.25, 0.2 and 0.15 respectively is a full swing), so the lines wander rather than pinning to one side, and drum hits kick the bass pen. Pen 4 draws the overall loudness (the average of all the bands) as back-and-forth hatching: none at 0.15 or below, full width at 0.6 or above, in proportion between, so quiet songs draw a thin band, loud ones a wide one, and a swell into a chorus widens it. The pens are stiff, lightly damped springs, so they overshoot and wiggle like real needles, and stop at the edge of their lanes. Paused, the paper keeps running and the pens rest at center, drawing four flat lines as if nothing is being recorded; each pen's "lately" holds still meanwhile, so playing again picks up smoothly instead of jolting. The inks are the visualizer's colors (one per pen in Multicolor and Custom), darkened 30% so pale ones read on the paper. 20 seconds of paper are kept.
- **Groove** (an original style) is a record turning under a steel tonearm with a ball pivot (after the app icon), the album cover as its label, its groove cut as the song plays. Loudness is kept 20 times a second of song time (from the bass, mids and treble, plus the beat); loud moments engrave a deep wiggle (depth by the square of the level, at most a third of the gap between turns), quiet ones a smooth line. The groove spirals from the edge to the label over the song's length, the record turning about once every 7 seconds, so the finished record shows the whole song. What's still to come is blank vinyl; moments played before the visualizer opened (not heard) are a plain gray line. Song time runs smoothly between the engine's position updates and follows seeks; a new song starts a blank record. In Multicolor and Custom the groove changes color from the edge inward.
- **Living Cover** (an original style) cuts the album cover into an 8×8 grid of tiles over a blurred, darkened copy of itself filling the screen. Bass and beats push the tiles out from the center (outer tiles further), the mids tilt them with neighbors in opposite directions, each tile lifts with its own band (bass in the middle, treble at the corners), and treble makes the tile edges sparkle in the visualizer's colors (one per row in Multicolor and Custom). With no music every tile is in place, so the cover is whole. An album without a cover shows tiles in the visualizer's colors.
- **Tapestry** (an original style) weaves the song into cloth from the top down, one row every half second of song time, under a steel loom beam whose shuttle crosses once per row trailing its thread. Each of 20 threads is a frequency band (the spectrum's bands averaged in groups, bass on the left), and each row keeps the loudest its band got during that half second: the louder, the wider (a third of the thread's space when silent, nearly all when loudest) and brighter (four shades). The whole song's rows fit the height (a song running past its stated length squeezes up to keep fitting), so the finished cloth shows the whole song. Below the loom the bare warp threads wait; rows played before the visualizer opened (not heard) are woven as bare threads. Song time is kept as in Groove (smooth between updates, follows seeks, a new song starts fresh cloth); pausing stops the weaving. In Multicolor and Custom each thread has its own color across the sweep.
- **Weather** (an original style) is a small landscape (two rolling hills with a row of trees) under a sky that follows the music, filling the screen behind the controls (darkened under the menu, and toward the panel sideways). The weather changes gradually: **cloud cover** follows how busy the music is (mostly mid-range and treble) at 0.4/s, so a calm passage clears the sky and a busy one clouds it over in a few seconds; the sun fades as clouds come in, and up to eight clouds appear and darken with the cover (one light cloud stays on clear days). The **wind** follows the bass (1.2/s): it drifts the clouds (always a little, never jumping), slants the rain, and bends and sways the trees. **Rain** follows the treble, only once the sky is more than half covered. **Lightning** strikes on a beat's rising edge (0.6 or more) in a storm, at most once every 0.6 s, as a jagged forked bolt that fades over half a second; the sky lifts by at most 10%, never a flash of the whole screen. The sky runs from the palette's darkest color overhead to its lightest at the horizon (a dusky sky in the accent, or the sweep's colors in Multicolor and Custom), turning storm gray as it clouds over.
- **Weather (Live)** (after Weather) is Weather's landscape under the real sky: the real time of day and, with Live Weather on, the real weather where you are set the scene, in natural colors (not the theme's; the Colors menu is hidden for it), and the music amplifies it (`LiveSky`): quiet passages show the weather gently, loud ones dramatically.
  - **Where:** with Settings > Weather (Live) > Live Weather on (off by default), the phone's location (Use My Location, on by default: asks for when-in-use permission once; approximate is enough; gives up after 30 seconds), else the Place typed there: a city and state ("Springfield, IL") or a ZIP code, or elsewhere a postal code with the country ("10115 Germany"). A bare city name also works, but gets Apple's single best guess among cities of that name. The Place is looked up with Apple's MapKit geocoder when the user presses Return or leaves the field, and the match shows under it ("Found: Springfield, IL, United States"), or "No match" with a hint; while typing, "Looking up…". The match (what was typed, its name and coordinates) is saved with the settings and used while the field still says the same, so the visualizer doesn't look it up again (it does if there's no saved match). The place found is reused until those settings change. With Live Weather off, or no place, the place is guessed from the time zone (its longitude, and a middling latitude: sunrise and sunset within an hour or two) and the weather is fair.
  - **The source** is chosen in Settings > Weather (Live) > **Source**: **Apple Weather** (default) or **MET Norway**. Apple Weather (WeatherKit, its current weather) blends observations and radar where Apple has them, so it more often matches the sky outside than a model forecast does (MET can say cloudy, 0.0 mm, while it's pouring). Its condition gives the sky and what's falling (rain for rain, drizzle, showers and storms; sleet for sleet, freezing rain or drizzle, wintry mix and hail; snow for snow, flurries and blizzards), showers (showers, isolated and scattered, sun flurries), thunder (thunderstorms, strong storms, tropical storms, hurricanes) and fog (fog, haze, smoke); its cloud cover and wind are used as given. How hard it's falling now wins over the condition: 0.1 mm an hour or more is rain even under a "cloudy" condition, and the rate sets the intensity (light under 2.5 mm/h, normal to 7.6, heavy above); with no rate, the condition does (drizzle and flurries light; heavy, blizzards and big storms heavy). Apple gets the same coordinates, rounded to 2 decimals. If Apple Weather fails (WeatherKit not set up for the build, Apple's service down, or over the monthly limit), MET Norway is used for that check, and Apple is asked again at the next. Changing the source restarts the scene's weather. The caption is then Apple's " Weather" mark (for dark backgrounds, from WeatherKit's attribution; "Apple Weather" until it loads), which opens Apple's legal attribution page, as Apple's terms ask.
  - **MET Norway's weather** is its forecast (`locationforecast/2.0/compact`), for the current hour: its symbol code gives the sky (clear, fair, partly cloudy, cloudy, fog), what's falling (rain, sleet, snow), how hard (light, normal, heavy), showers and thunder; its cloud cover and wind speed are used as measured. Coordinates are rounded to 2 decimals; every request names the app and a contact (Info.plist `METNorwayContact`; with none, nothing is asked); a forecast is reused until its `Expires` time, then checked with `If-Modified-Since`; it's checked every 10 minutes while the visualizer is open, and never while it's closed. If MET can't be reached, the last forecast stands (kept in memory only, so no location is stored). A caption under the menu credits the source: Apple's mark (above) or "Weather: MET Norway" (the data is CC BY 4.0), or says it's finding the location, has no location ("allow it, or set a city in Settings"), or that the weather is unavailable.
  - **The weather, amplified by the music** (its loudness, followed within a second or so): clouds start at the real cover and billow thicker in busy music, and past half cover a deck of cloud closes over the sky from the top; rain, sleet or snow fall at the real strength, from about half of it in quiet passages to twice it when loud (rain as slanted streaks, snow as flakes swaying and swirling in the gusts, sleet as both); the real wind blows, gusting with the bass, bending the trees and moving the clouds; a real thunderstorm strikes lightning on the beats (bolts at most every 0.6 s, with a slight lift of the sky); fog lies thick in calm passages, as a haze and drifting bands over the hills, and thins in busy ones. Heavy weather darkens the clouds, sky and land, hides the sun behind thick cloud, and hides the stars and moon (half cover dims them). The first frame starts as the weather is, rather than clearing for a moment. Birds don't fly in rain, snow, storms or fog; shooting stars need open sky; fireflies stay away in rain and snow.
  - **Debug builds** add a Debug: Weather section to the style menu while Weather (Live) is showing, to force a weather (Clear, Partly Cloudy, Cloudy, Light Rain, Downpour, Thunderstorm, Sleet, Snow, Fog) and a time of day (Dawn, Sunrise, Day, Sunset, Dusk, Night).
  - **Time of day** comes from where the sun is, worked out on the phone (`SkyClock`): night (sun more than 12° below the horizon), dawn and dusk (twilight), golden hour (the sun within 10° of the horizon), and day. The sky, sun, clouds and hills blend smoothly between them, through deep blue night, purple and rose twilight and an orange golden hour to blue day. The sun rises on the left and sets on the right at its real height. The moon shows at night in its real phase (lit on the right while waxing, the left while waning), with a soft glow.
  - **The music's mood**: how energetic it is (loudness and busyness) and how bright (treble against bass), both followed over a few seconds, so the scene breathes with the song. Calm music makes the events below rarer; energetic music, more frequent.
  - **Playing along with the instruments** (the spectrum as it is each frame, as Chrome uses it): a horizon light of 24 columns of added light (always brighter than the sky behind them; quiet bands lifted so they still show), one per slice of the spectrum (bass on the left, treble on the right), each rising with its instruments; rose and amber at dusk and dawn, green into violet at night, gold by day (nearly as strong as at night, so it shows against the bright sky), dimmed behind cloud. By day the sun is golden with a white-hot center, a bright corona and a wider glow that swells on each beat; its 12 rays are a radial spectrum, each a slice of it (bass at the bottom), stretching and thickening with its instruments. Treble adds shimmer to the rain; after dark the mid-range lights the clouds a little from within.
  - **Every beat:** the horizon glows up from the ground, the stars flare (the bigger ones most, the brightest into a soft cross), the sun's and moon's glow swells, the trees kick, every firefly flashes at once, and the birds' wings beat down, all fading within a quarter second.
  - **Night and twilight** (the sun more than about 0.3° below the horizon for shooting stars): about 140 stars, more toward the top, fade in as the sky darkens; each twinkles at its own pace, faster and brighter with the treble. Beats send shooting stars (at most one every 4 seconds in calm music, every 0.8 in energetic). In an energetic stretch, every fifth one is a comet instead, slower with a long blue-white tail, at most every 30 seconds. Fireflies drift over the hills at dusk and night, 3 in calm music up to 10 in energetic, glowing faintly with the mid-range and flashing together on each beat.
  - **Day and twilight** (until the sun is about 6.6° below the horizon): the sun's rays play the spectrum (above) when the sky is clear. When the music builds (louder than a few seconds before) or is energetic, flocks of 3 to 9 birds cross the sky in a loose V, flapping (at most every 20 seconds in calm music, every 6 in energetic).
  - **Always:** the clouds sail with the real wind and the song's overall energy (not each bass note, so they don't race); the bass gusts the trees.
- **Chrome** (an original style) is a blob of liquid metal, like the steel of the app icon, reflecting the album cover (a Metal shader, `Chrome.metal`). Its outline is 128 points around the middle, joined by smooth curves: each of the spectrum's bands pushes out a bulge at its own height, mirrored left and right, bass at the bottom and treble at the top, blending with its neighbors (at most 0.4 of the resting size, which is a third of the drawing space's shorter side); a slow wobble keeps it moving when quiet, and a beat swells it all by 8% and sends rings across its surface. A strong drum hit (beat 0.6 or more, at most every 0.25 s) also **splashes** three to five droplets (each a tenth to a fifth of the blob's size) from random places just past its edge, flying outward; they slow and are pulled back like beads of mercury, stopping at the edge of the free space if they reach it, and melt back into the blob about 2.5 seconds later (at most 16 at once). The blob and droplets are drawn as one surface that melts together where they come close, so a droplet stretches a neck of metal as it leaves and as it rejoins. Inside, it's shaded as a dome: the surface's slope picks which part of the cover it reflects, like a polished ball, toned 30% toward steel, with a highlight at the top left and the visualizer's colors catching its edges (four, going around it). Without a cover it reflects plain steel, light above and dark below.
- **Typeset** (an original style) sets the song's title big in heavy rounded type (SF Pro Rounded), with the artist below, centered: the title as large as fits in up to three lines (76 pt down to 26 pt) and the artist at about 40% of that in up to two, leaving a quarter of the height and 6% of the width either side spare for movement; letters moving past the drawing space are still drawn, so nothing is cut off before the screen's edge. The small title at the bottom is hidden, since the screen is the title. The letters move with the feel of the track, each riding springs toward where the music puts it, so they leap and settle rather than tremble. Each plays its part of the spectrum by its place in the words (the title's first letter bass, its last treble; the artist's spread the same way), averaging its band with two either side. A letter **jumps when its part gets louder than it has been lately** (its level compared with its own average over about the last second; a rise of 0.4 is a full jump of 0.6 of the font size, stretching it up to 30% taller from its baseline) and dips a little (up to 0.15) when it gets quieter; as a new level becomes normal it settles back home, so a loud song keeps the words in place and only the changes move them. It brightens with how loud its part is (very quiet parts, below 0.08, stay dim), the loudest glowing. A bass hit (the bass rising above its own recent average; a rise of 0.3 is full) thumps the whole title up together (up to 0.35, lifting without stretching); a steady bass line doesn't. Treble leans the letters all the same way (up to 0.18 rad at the treble end, so neighbors don't collide), and loudness swells the words by up to 12%. A strong drum hit (beat 0.6 or more, at most every 0.3 s) makes the letters jump out: each pops bigger and is thrown, mostly upward and with a spin, then springs back. A **calm** measure follows how loud the music has been over the last few seconds (0.5/s): soft passages float the letters on a slow wave (up to 0.14 of the font size) with a gentle sway, and the springs go from loose and drifting when calm to tight and punchy when loud. The artist moves half as much as the title. In Multicolor and Custom the letters run through the sweep.
- Colors, from the same menu: **Accent** (the theme's accent); **Multicolor**: in a Catppuccin theme its 14 accents in palette order blended across the screen, otherwise a sweep of hues starting from the accent (red → orange → yellow → green → teal for Bzide Red, blue → purple → pink → orange for blue); and, in Catppuccin themes only, **Custom**: the accents the user picks ("Choose Custom Colors…" in the menu opens 14 swatches; at least two; mauve, pink, peach, teal and blue to start), blended in palette order. Custom is remembered; in a non-Catppuccin theme it shows as Multicolor. Bars take a color each; the waveform a left-to-right gradient; Plasma loops through four of them (in Accent, shades of the accent from deep to light). Style and colors are remembered on the device. While it's open the audio tap runs and the screen doesn't dim; closing it turns both back to how they were.
- Each frame takes the latest 2048 samples (mixed to mono), applies a Hann window and a Fourier transform, and takes each band's peak on a decibel scale (−75 dB empty to −15 dB full), so quiet passages still move. Bars rise quickly and fall at most 1.6 of their height per second. When no new audio has arrived for a quarter of a second (paused, between songs, or the tap isn't running) they fall to a sliver rather than freezing.
- The waveform shows 512 samples (about 12 ms) starting at a rising zero crossing, so it holds still like an oscilloscope, averaged to 128 points and scaled up 2.5× for typical music levels. It eases halfway to each new frame, and flattens out when the audio stops.
- For a radio station it shows "The visualizer isn't available for radio.", and over AirPlay "The visualizer isn't available over AirPlay." (neither can be tapped; see Audio levels). Both follow changes while it's open.

### Spin Off and Keep Spinning

- **Spin Off** (a song's long-press menu, an artist's long-press and ⋯ menus, and Now Playing's ⋯ menu for the current song) plays endless music grown from a song or an artist. A song plays first, then the first batch; an artist starts straight into its batch. Now Playing's queue heading reads "Spin-off of “…”" while it lasts.
- **Where the songs come from**, in order, so it works on any server: the server's similar songs (`getSimilarSongs` for a song, `getSimilarSongs2` for an artist; Navidrome needs an agent such as Last.fm, and returns nothing without one), shuffled; else random songs from the seed song's genre (`getRandomSongs` with `genre`); else random songs from the whole library. Songs already in the queue and repeats are left out; a batch is up to 25 songs. A mix says why in a banner for 5 seconds ("Similar songs aren't available from this server, so this is a mix of Rock."). If nothing can be found (offline), the queue is left as it was and a banner says so.
- **It keeps going:** whenever the current song changes and 2 or fewer songs are left after it, the next batch is fetched and added at the end without a gap. Skipping songs while a batch is being fetched doesn't lose it, and if the queue is low again by the time it arrives, another is fetched. The seed is saved with the queue, so it carries on after a restart (a queue saved before spin-offs existed isn't one). Playing anything else ends it. Starting a spin-off turns repeat off, since it's endless; turning repeat back on afterwards loops the queue instead of growing it.
- **Keep Spinning** (Settings > Playback, off by default): when any queue reaches its last song, Bzide spins off from that song the same way, so the music keeps going, and the queue becomes a spin-off. Not with repeat on, and not for radio.

- **Meh songs** (rated Meh, 1 or 2 of the server's 5 stars) are left out of Random Mix (from the server and from downloads), Spin Off's and Keep Spinning's suggestions, unless Settings > Playback > Include Meh Songs is on (off by default; called Include 1–2 Star Songs with Use Simplified Rating off, and Mix My Cuts' explanation and hint then say 3 stars or more for Love or Like). A song the user spins off from plays even if it's Meh, since they picked it. Unrated songs, and servers without ratings, are never left out. Mix My Cuts never includes Meh either way. Random Mix still asks for 50 songs, so a mix can be a few short when some were Meh.

### Volume normalization

- Settings > Playback > Volume Normalization: Off (the default), By Track or By Album. It evens out loudness between songs with their ReplayGain (OpenSubsonic `replayGain` on each song: track and album gain in dB, and track and album peak), which Navidrome has when the music files are tagged with it; it doesn't calculate it. Songs without it, and radio, play unchanged.
- **By Track** uses the track's gain (falling back to the album's), **By Album** the album's (falling back to the track's), so an album's quiet and loud songs keep their difference. A boost is capped so the song's peak (of the gain used) stays at full scale, so normalization never clips.
- The gain is applied in each item's audio tap (the same one the visualizer measures with), multiplying the samples on the audio thread without locks or allocation, so it can boost as well as cut. It's set when a song is loaded; changing the setting applies at once to the current, next and (for repeat all) first songs, without interrupting playback. The tap attaches as the item loads, normally before it's heard.
- Now Playing's quality line adds the adjustment in use, e.g. "FLAC · 964 kbps · −4.2 dB" (nothing when there's none).

### Equalizer

- **Settings > Equalizer**, and Now Playing's ⋯ > **Equalizer** (a sheet, half or full height): on or off (off by default), a **preset**, and ten **bands** one octave apart (32, 64, 125, 250 and 500 Hz, 1, 2, 4, 8 and 16 kHz), each −12 to +12 dB in half-decibel steps. Presets: Flat, Bass Boost, Bass Reducer, Treble Boost, Treble Reducer, Vocal, Loudness, Late Night, Rock, Pop, Jazz, Classical, Electronic, Hip-Hop, Acoustic, Small Speakers, and **Custom** (the user's own). Moving a band copies the preset's gains into Custom and switches to it; Custom has Reset to Flat. Settings shows "Off" or the preset's name. The bands are disabled while the equalizer is off.
- **Kept per iPhone**, not per account (it's about the listener's ears and speakers): a device setting that an account switch and Restore Default Settings leave alone.
- **How it's applied:** in each item's audio tap, the same one that measures for the visualizer and applies volume normalization, after the source audio and before the normalization gain (so the visualizer shows what's heard). Each band is a peaking filter (Audio EQ Cookbook, one octave wide, Q 1.414); a band at or above 45% of the sample rate is left out. To keep boosted bands from clipping, the audio is first lowered by the largest boost (up to 12 dB). Changes reach every playing item at once and glide in over about 20 ms (1,024 frames), so moving a slider doesn't click. With the equalizer off or flat, the audio passes through untouched, bit for bit.
- **Real-time rules:** the tap's storage is reserved when its format is known; while playing it never allocates, locks or waits (a settings change is picked up on the next buffer the tap can read it without waiting).
- **Where it applies:** songs (streamed or downloaded) played on the iPhone's speaker, wired headphones and Bluetooth. **Not radio stations** (any kind: AVFoundation plays endless streams through a path that skips audio taps, see Audio levels) and **not AirPlay** (the receiver decodes the audio; it never passes through the phone's audio path). Nor audio that isn't 32-bit float in the tap (it then plays untouched, as for normalization).
- **Is it heard?** Each tap notes when it last processed audio. While the equalizer is on and something is playing, Now Playing's status line ends with **EQ** (in the accent) when a tap processed audio within the last 1.5 seconds and the output isn't AirPlay, else **EQ unavailable**; the Equalizer screen says "Applied to what's playing" or "Can't be applied to what's playing (radio or AirPlay)". Both are checked once a second. Paused or off: nothing shown.

### Sleep timer

- Now Playing's moon button (top bar, beside Save Queue) offers 15, 30 and 45 minutes, 1 hour, and End of Song; while a timer runs it also offers Turn Off Timer, and the button shows a filled moon and when the music will stop, counting down each second in the accent: the time left on the timer ("14:53"), or for End of Song the time left in the song ("End" if its length isn't known). Choosing again replaces the running timer.
- **Timed:** it counts to a fixed clock time, so it stays right with the screen locked and the app in the background. Over the last 10 seconds the music fades out (the player's own volume, on top of the system volume), then pauses, and the volume goes back to normal so the next Play isn't silent.
- **End of Song:** waits for the song playing when it was set. The song fades out over its last 4 seconds (position estimated smoothly between the engine's updates), and when it ends the music pauses: the next song, already started silently for gapless playback, is paused at once and the volume restored. Skipping to another song before the end moves the timer to that song; the queue running out ends it. A radio station has no end, so End of Song isn't offered while one plays (the timed choices work as usual: the station fades out and pauses), and starting a station while End of Song is set turns the timer off, leaving the station playing.
- Pausing early doesn't cancel it; it ends quietly. Turning it off mid-fade restores the volume. The timer isn't saved, so a forgotten one can't stop the music another day. The fade volume is kept if the player is rebuilt after a media services reset.

### Lyrics

- Now Playing's speech-bubble button (between AirPlay and the visualizer's waveform) opens the song's lyrics full screen over a blurred, darkened copy of its cover (a dark gradient without one), with a close button at the top and the title, artist, previous, play/pause and next at the bottom. It follows the queue: skipping changes the lyrics.
- **Where they come from**, in order, the first that has them winning: (1) the server's synced lyrics, (2) LRCLIB's synced lyrics, (3) the server's plain lyrics, (4) LRCLIB's plain lyrics. So synced lyrics win wherever they come from, and the server wins between equals. The server is asked for synced lyrics with OpenSubsonic `getLyricsBySongId` only if it advertises the `songLyrics` extension (checked once per sign-in; a failed check is tried again), and otherwise, or when it has none, for plain lyrics with classic `getLyrics` (by artist and title). Navidrome reads lyrics from the music files' tags and `.lrc` files beside them. A set marked synced with any untimed line is treated as plain; a structured set's `offset` (milliseconds) shifts its lines and word times.
- **LRCLIB** (lrclib.net, a free lyrics database) is asked only when Settings > Lyrics > Find Lyrics Online is on (off by default) and the server has no synced lyrics. A request sends the song's title, artist, album and length. Matching is strict, since lyrics for another recording run out of step: (1) an exact lookup (`/api/get`); (2) if that misses and the title has a version note that doesn't change the recording ("(2025 Remaster)", "- Single Version", "[Explicit]", "(Deluxe Edition)", a year, "feat. …"), the exact lookup again without it; (3) a search by the cleaned title and artist (`/api/search`), where every result is scored and the best kept: it must be within 2 seconds of the song's length, have the same title (after cleaning) and artist (compared without accents, case or punctuation, "&" as "and", so "Motley Crue" finds "Mötley Crüe"), and the same kind of performance (a note like Live, Acoustic, Unplugged, Demo, Instrumental or Remix in the title or album must be on both or neither); closer length, the same album and synced lyrics rank higher. A result that doesn't qualify is turned down: no lyrics beat lyrics for another recording. Results without names aren't held against them. An exact match with synced lyrics (or marked instrumental) is used at once; one with only plain lyrics is kept while the search looks for a synced match, which wins if found (synced lyrics win wherever they come from). An exact lookup that fails (on a miss, `/api/get` looks the song up elsewhere, which can be slow or fail) doesn't end the lookup: the search is still tried, and only a failed search with nothing else found counts as LRCLIB not reachable. It identifies the app in its User-Agent, uses its own cookie-less session, and sends nothing else. LRCLIB's lyrics are credited ("Lyrics from LRCLIB") at the end. **Server-side alternative:** Navidrome 0.63 and later can find lyrics online itself with the community [Navidrome Lyrics Plugin](https://github.com/J0R6IT0/navidrome-lyrics-plugin) (nd-lyrics; added to the server's `LyricsPriority`), which serves them to every app as server lyrics, optionally writing sidecar files; Bzide needs nothing for it (confirmed by the owner 2026-10-22, with Find Lyrics Online off). The Settings > Lyrics footer suggests it.
- Results are kept for the session (per song and setting), so reopening is instant. A result where either source failed (the server or LRCLIB couldn't be reached, or answered with an error) isn't kept, so reopening tries again. Closing the lyrics screen mid-search cancels the lookup, which then shows and keeps nothing (a cancel isn't a failure), and reopening starts afresh. LRCLIB failures are logged in Console (category LRCLIB) by kind only, a URLError code, HTTP status or unreadable reply, with no song details.
- **Synced lyrics** (LRC: `[mm:ss.xx]` line times, several times for a repeated line, `[offset:±ms]`, metadata tags skipped): lines are big and bold, left-aligned. The current line is the last to have started, shown 0.15 s early so the eye arrives with the voice; it's bright and sharp, its letters lighting up as each word is sung (60% bright before, full once sung), and the view scrolls smoothly to keep it about a third of the way down. Other lines are dimmed (35%), slightly smaller and softened, more so further away (up to 3 lines). An empty line is an instrumental break: three dots that breathe while it's current, otherwise almost no space. Lines fade out toward the top and bottom bars.
- **Word timing**: exact where the lyrics have word times (enhanced LRC, `<mm:ss.xx>` before each word, in a server line or an LRCLIB file); each word lasts until the next, the last at most 1.5 s. Otherwise estimated: a line's words share the time until the next line by their rough syllable counts (groups of vowels, a silent final "e" not counted), taking at most 90% of the gap and no more than 0.32 s a syllable plus 0.6 s, so a line before a long break isn't stretched out. Song time runs smoothly between the engine's position updates and follows seeks.
- **Timing fix:** for synced lyrics, a Timing button (top right) shows them earlier or later, half a second a tap, up to 30 s either way, for lyrics that run behind or ahead of the singing; the button shows the shift ("1.5 s earlier"), and Reset Timing clears it. It's remembered for the song on this device (the last 1,000 songs fixed). Line following, word lighting and tapping a line all use the shifted timing.
- **Wrong lyrics?** LRCLIB's lyrics are sometimes for another recording of the song (another version, out of step with the singing). With Settings > Lyrics > **Wrong Lyrics Button** on (off by default; shown under Find Lyrics Online while that's on), while lyrics from LRCLIB show, a **Wrong lyrics?** button (top right, beside Timing) offers **Try LRCLIB's Next Match** and **Don't Use LRCLIB for This Song**. While a match other than LRCLIB's best is showing (the user's choice), the button's text and icon are in the accent color, so it's clear the lyrics were changed. The next match is the one after what's showing among every LRCLIB entry that fits the song, best first: LRCLIB's search (`/api/search`, which includes the exact matches; not `/api/get`, which on a miss looks the song up elsewhere and can be slow or fail), judged by the same strict matching as above and ordered by score, leaving out entries whose words are the same as an earlier one's or as what's showing (timing and spacing aside), so each try is really different. A search that times out or gets a server error is tried once more. Past the last, an alert says LRCLIB has no other version and offers Don't Use LRCLIB for This Song, Back to the Best Match (after a change) or Keep These. Don't Use LRCLIB shows the server's plain lyrics if it has them, else No Lyrics with the note "You chose not to use LRCLIB's lyrics for this song."; the button then reads **LRCLIB off** and offers **Back to LRCLIB's Best Match**. The choice (an LRCLIB entry by its id, or none) is remembered for the song on this device, with the account's settings (kept by Restore Default Settings, like the timing fixes; up to 1,000 songs, oldest dropped first); next time the chosen entry is found by its id among the search's matches (LRCLIB's get-by-id endpoint, `/api/get/{id}`, answered 503 most of the time when tried on 2026-10-22, so it isn't used); if LRCLIB no longer has it, or it can't be found just now, the best match is used and the choice is kept. If LRCLIB can't be reached, an alert says so and nothing changes. The server's own lyrics are never affected: the button only appears for LRCLIB's. With the setting off, choices made before are ignored (every song gets LRCLIB's best match) but kept, so turning it back on brings them back.
- Tapping a line jumps the song to it. Scrolling by hand stops the view following for 3 seconds after the scroll ends, then it returns to the current line.
- **Plain lyrics** scroll freely, all lines bright, verses separated, under a note that they aren't synced.
- With no lyrics anywhere: "No Lyrics: There are no lyrics for this song.", followed by a note saying why nothing was found online, so a gap in LRCLIB can be told from a strict match: with Find Lyrics Online off, that turning it on would also search LRCLIB; if LRCLIB couldn't be reached, that; if it had nothing, "LRCLIB has no lyrics for this song either."; and if it only had results that were turned down, the reason for the closest one, which is a different length first (e.g. "a version 4 seconds longer", which would be out of step), then another performance ("only has lyrics for a live version"; for a studio song, a title or album with a performance word counts, e.g. "Live Through This"), then another artist, then another title. An instrumental (LRCLIB says so): "Instrumental: This song has no words." Radio: "Lyrics aren't available for radio." If neither source could be reached: "Couldn't Load Lyrics" with a hint to check the connection.

### Lock screen, Control Center and remote commands

- Now Playing shows the current track's title, artist, album, artwork, duration and elapsed time. An empty queue clears it.
- A restored queue is sent to Now Playing paused at its saved position, but iOS 27 doesn't show the app in Control Center or on the lock screen until it has actually played since launch (observed on device, 2026-10-10). After the first play, it shows normally.
- Updates are sent on play, pause, seek, track changes and status changes, not on every time tick: the system extrapolates elapsed time from the playback rate (1 while playing, 0 otherwise, including while buffering). Unchanged info is not re-sent.
- Artwork is fetched by cover art id after the text appears. If the track changes before the image arrives, the late image is discarded.
- Remote commands (lock screen, Control Center, headphone buttons, CarPlay) map to the engine's own commands: play, pause, toggle, next, previous, and seek by dragging the progress bar. They follow the same rules as the in-app buttons.
- Next is disabled on the last track. Previous is always enabled, because it restarts the track when there's nothing before it.

### Network recovery

- If the current track fails while the user is listening, status becomes **reconnecting** and the engine retries automatically: it builds a fresh stream URL and resumes at the last known position. Retries wait 1, 2, then 4 seconds. After the third retry fails, status becomes failed with the error message.
- The retry budget resets only after 10 seconds of uninterrupted playback following a retry, so a stream that keeps dropping right after starting doesn't retry forever.
- If the current track fails while paused, status becomes failed with no automatic retry. Play retries it.
- A stall (the player ran out of buffered audio) gets 10 seconds to recover by itself. If it isn't playing by then, it is treated as a failure and the retries above apply.
- When the network comes back (offline to online, or a switch such as Wi-Fi to cellular), a pending retry runs immediately. If retries had run out while the user was listening, playback is retried once more with a fresh budget. A paused player is never started by this.
- If the preloaded next track fails, it is rebuilt in the background (same 1, 2, 4 second schedule) without interrupting the current track, so the hand-over stays gapless.
- Pause, play, next, previous, jump and starting a new queue cancel any pending retry. So do interruptions and losing the output device. A track change gives the new track a fresh retry budget.
- While reconnecting, the lock screen shows the track as paused (playback rate 0).

### Scrobbling

- A track is scrobbled once it has played for 50% of its duration or 4 minutes, whichever comes first. If the duration is unknown, 4 minutes.
- Only time actually listened counts toward the threshold. Seeking forward does not add to it; seeking back does not remove from it. Listening is counted from the player's time ticks (about every half second); any forward jump over 2 seconds counts as a seek.
- A play begins when a track becomes current (natural advance, next, previous, jump, new queue), when previous restarts the current track. Seeking within a track does not start a new play. A queue restored after relaunch starts a fresh play at the saved position; listening from before the relaunch is not counted.
- Each play is scrobbled at most once, with the time the play began.
- "Now playing" is sent once per play, when it first plays (including when one track flows straight into the next). It is best effort and never retried.
- Scrobbles are saved to `Application Support/PendingScrobbles.json` before sending and removed only once the server accepts them. They are sent oldest first, never in parallel, stopping at the first failure. Pending ones are retried at the next scrobble and at launch.
- Known limit: if the server records a scrobble but the reply is lost, it will be sent again and may count twice.
- **Last.fm and ListenBrainz** aren't contacted by Bzide. Plays go to the user's server only; Navidrome forwards them to the services each user links in its web interface (Personal settings), so it works the same from every client and no service credentials are on the phone. Settings > Scrobbling says so (Gitea #18).
- **Send Plays to Server** (Settings > Scrobbling, on by default): off, nothing about listening is sent to the server from this iPhone: no "now playing" and no plays, and plays made while it's off are never sent later (they aren't saved). Plays saved while it was on are still delivered. The server's play counts and lists built on them (Recently Played, Most Played, Spin It Back) stop updating from this phone; History on the phone isn't affected.

## Queue

- The queue is an ordered list of entries plus a current position. Each entry has its own id, so the same song can appear more than once and the UI and player can tell the copies apart.
- A new queue starts at the requested index, clamped into range. An empty queue has no current entry.
- Next moves to the following entry. At the last entry it does nothing.
- Previous: if the current track has played more than 3 seconds, restart it. Otherwise go to the previous track. On the first track, restart it.
- Jumping to an entry that isn't in the queue does nothing.
- Appending adds to the end. Appending to an empty queue makes the first added song current.
- Clear up next removes every entry after the current one. The current track keeps playing (the player drops its buffered next track), and when it ends the queue is done, as at the end of any queue.
- The queue as shown is the current entry and what's after it. Entries already played are kept out of sight, so previous can still go back to them, until the queue ends or is replaced.
- Play next inserts songs right after the current entry, ahead of everything else upcoming; the most recent play next goes first. The current track keeps playing; the track the player had buffered as next is swapped for the first inserted song, so the handover stays gapless. On an empty queue it behaves like appending (queued, not started). A queue restored after relaunch and not yet played isn't loaded just to insert.
- **Editing up next.** In Now Playing's queue, swiping an upcoming song left offers Remove, and long-pressing and dragging an upcoming song moves it. Only upcoming entries can be edited: the current song stays at the top (neither removable nor movable) and played entries stay hidden and untouched. Removing takes out just that entry, even if the same song is queued again. If the edit changes which entry plays next, the player's buffered next track is swapped, without interrupting the current one, so the handover stays gapless; an edit further down leaves the buffer alone. Edits are saved with the queue. On a restored queue that hasn't been played yet, editing doesn't load the player.
- **Going from the queue.** Long-pressing a song in Now Playing's queue (the current one or any upcoming) offers Song Info, Go to Album and Go to Artist (when the server gave their ids; nothing for a station). Now Playing's ⋯ menu offers the same for the current song, with Album Info: Spin Off, Song Info, Album Info, then Go to Album and Go to Artist, then Save Queue as Playlist…. Albums and artists open inside Now Playing. There's no Artist Info: an artist's page holds their biography.
- **Shuffle** is a mode, turned on and off by the button left of the playback controls (gray when off, the accent color when on).
  - Turning it on shuffles the upcoming entries; the current song plays on, and played entries are untouched. The original order is remembered.
  - Turning it off puts the upcoming entries back in that original order; the current song plays on. Entries added while shuffled (play next, add to queue) keep their places; removed ones are simply gone; reorders made while shuffled are undone.
  - Shuffle buttons elsewhere (album, playlist, genre, menus, Siri) start the songs in a random order with shuffle on, so turning it off continues with the songs not yet played in their original order. Play, and anything else that starts a new queue in order, turns shuffle off.
  - The mode and the original order are saved with the queue (a queue saved before shuffle existed has it off). It can't be turned on for a radio station.
  - Either way, if the entry that plays next changes, the buffered next track is swapped without interrupting the current one; otherwise the buffer is left alone.
- Repeat has three modes, stepped through by one button: off, repeat all, repeat one. It's saved with the queue (a queue saved before repeat existed has it off) and stays as set when a new queue starts.
  - **Off:** when the last track ends, the queue is done (see Playback).
  - **Repeat all:** after the last track the queue starts again from the first entry, including entries already played. On the last track the player preloads the first, so the wrap is gapless, and next wraps too. A queue of one track plays it again.
  - **Repeat one:** the current track plays again when it ends, as a new play (scrobbled and added to history each time). Nothing is preloaded, so there is a brief gap at the restart. Next and previous still move between tracks, and repeat one stays on.
  - Changing the mode while playing swaps the preloaded next track to match, without interrupting the current one.

### Persistence

- The queue and the position within the current entry are saved as JSON to `Application Support/PlaybackQueue.json`, replaced atomically so a crash never leaves a half-written file.
- The file stays writable while the device is locked (after the first unlock since boot), because saves happen during locked-screen playback.
- A saved file that can't be read is reported, not crashed on; the app starts with an empty queue. A saved current index outside the entries is clamped into range.

## Library

- **The Library screen** shows, by default and in this order: Random Mix, Mix My Cuts and Spin the Dial (together in one block), then links to Artists, Albums, Playlists, Favorites, Genres, Radio, Downloaded, History and Wishlist (links next to each other are grouped in one block). **Edit** (top right, beside Settings) opens Edit Library: tap an item to show or hide it, drag to reorder; Reset restores the default. Carousels (rows of album covers: Recently Added, Recently Played, Spin It Back) are hidden by default, to keep Library minimal, and are marked in Edit Library with a row-of-panels icon at the end of the line. The layout is saved on this device for the signed-in account (each account has its own; see Account) and kept across sign-outs. A layout saved by another version still loads: unknown items and repeats are dropped, and items added since appear, shown, in their usual place (after the item that comes before them by default, e.g. Mix My Cuts after Random Mix). With everything hidden, the screen says to tap Edit. Recently Added is only fetched while it's shown.
- **Favorites** (a Library link) lists everything favorited, from `getStarred2`: songs first (Play, Shuffle, tap a song to play the list from it, the song row menu), then albums and artists (with their row menus). It reloads each time it opens; anything unfavorited in this session, here or elsewhere, leaves the list at once. With nothing favorited it says how to add some. A bar at the top shows All, Songs, Albums or Artists; the search field narrows the list as you type (a song's title, artist or album; an album's name or artist; an artist's name; case and accents ignored); the funnel offers Sort By (Recently Favorited, the default, newest first from the server's `starred` date, undated ones last; Name; Artist, then name), a rating (Any, Love, Like, Meh, Unrated, as the server sent it) and Downloaded Only (songs and albums on this device; no artists), with Clear Filters. While a rating or Downloaded Only is on, the funnel fills in and a line under the bar names them, with Clear. Play and Shuffle play the songs shown. Nothing matching: "No Results". The scope, filters and order are remembered on this device; the search text isn't.
- **Genres** is also a Library link, opening the same genre grid as Search.
- **Song Info and Album Info** (a song's long-press menu, a queue row's and Now Playing's ⋯ menu; an album's long-press and ⋯ menus, and Now Playing's ⋯ menu for the current song's album) open a full-height sheet with the cover and name, then everything the server says, in groups, each only with the rows it has: **General** (title, artist, album, album artist when different, track and disc, year, genres, composer, length, BPM, mood, comment), **Audio** for songs (format, bit depth and sample rate e.g. "24-bit / 96 kHz", channels, bitrate, file size, ReplayGain), and **Library** (plays, last played, added, rating, favorite). Albums show year (with "originally …" when the original release differs), genres, release type (not when it's just "Album"; compilations say so), record label, songs and length. Plain Subsonic gives fewer of these; Navidrome's OpenSubsonic fields fill in the rest; 0 and empty values count as not given. A song's Info shows what's at hand at once, then the server's latest (`getSong`, for current play counts); an album's fetches it (`getAlbum`). Values can be selected and copied. Song details are kept with the saved queue.
- **Album pages** show a details line under the artist and year: genre, number of songs and length, e.g. "Contemporary R&B · 18 songs · 1 hr 2 min" (whatever the server gives). The record label is in Album Info.
- **Settings > Developer > Debug Player** opens the bare player kept for testing playback (it used to be a toolbar button on Library).
- **Loading.** Each screen fetches what it shows when it appears. Until that arrives it shows loading; if it fails with nothing to show, the error and a retry. A refresh keeps the current content on screen; if the refresh fails, the content stays and the error is reported alongside it. A load that's still running when the screen goes away is dropped, and runs again when the screen comes back.
- **Recently Added** (a carousel, hidden by default; switched on in Edit Library) shows the 15 newest albums (`getAlbumList2`, type `newest`) as a row of covers with name and artist. Tapping a cover opens the album; long-pressing gives the album's row menu (below). See All opens the album list in Recently Added order. Tapping the heading collapses or expands the row; this is remembered on the device. The row reloads whenever Library is shown or pulled to refresh, keeping the old covers on screen meanwhile; if it can't load, it says why with Try Again.
- **Row menus.** Long-pressing a row acts on it without opening it:
  - Artist (Artists, Search): Play, Shuffle, Play Next, Add to Queue, Add to Playlist…, Favorite, Rate. The artist page's ⋯ menu has the same.
  - Album (Albums, Recently Added, an artist's page, Search): the same five, Download or Remove Download, Favorite, Rate, and Go to Artist (not on the artist's own page).
  - Playlist (Playlists): the same five, and Download or Remove Download; for the user's own playlists also Rename…, Share Playlist and Delete Playlist… (see Managing playlists).
  - Download (Downloaded): the same five, using the stored songs, so they work offline, and Remove Download.
  - Song (album and playlist pages, Search, History, Downloaded): Play Next, Add to Queue, Add to Playlist…, Download or Remove Download, Favorite, Rate, then Go to Album and Go to Artist (when the server gave their ids; Go to Album is left out on the album's own page, including its downloaded copy).
  - The songs are fetched first: an album or playlist in its order; an artist's albums oldest first by year (albums without a year last, otherwise in the server's order), each in track order, fetching at most 4 albums at a time. If any fetch fails, nothing happens and the error is shown ("Couldn't Load Songs"). A second choice for the same item while it loads is ignored.
  - An artist with more than 100 songs (counted from their albums' song counts) asks first, e.g. "Add 340 songs by X to the queue?"; for Add to Playlist the question comes before the playlist sheet.
- **Genres.** Before anything is typed, Search shows the library's genres (`getGenres`) as a two-column grid of tiles, most albums first (ties by name; genres with no albums are left out, and one whose count isn't given goes last). Each tile has a color that stays the same for that genre (system colors, or the Catppuccin accents in a Catppuccin theme) and one of the genre's album covers tilted in its corner: the first album `getAlbumList2` gives for `byGenre`, fetched when the tile first appears and kept for the session (a genre with no cover just shows the color; a failed fetch is tried again when the tile next appears). Typing a search replaces the grid with results; clearing it brings the grid back.
  - Tapping a tile opens the genre's page: Play and Shuffle, then its albums (`getAlbumList2` `byGenre`, paged like the album list, with the album row menu). Long-pressing a tile offers Play, Shuffle, Play Next, Add to Queue and Add to Playlist… for the genre.
  - A genre's songs are up to 500 from `getSongsByGenre`, in the server's order (Shuffle shuffles them).
- **Album lists** come in these orders: recently added, recently played, most played, name, artist, random, starred. They load 40 albums at a time; the next page is requested when the user scrolls within 10 albums of the end, and a page shorter than 40 means there are no more. An album already shown is never shown twice, even if the library changed between pages; the next request still starts where the server's previous page ended. If a page fails, scrolling doesn't retry it; an explicit retry does. Random shows a single page, and a refresh picks again, because paging a random list would repeat albums. Changing the order replaces the list, and a late reply for the old order is ignored.
- **Search** runs 300 ms after the user stops typing, with surrounding spaces ignored. An empty query clears the results. While a new search runs, the previous results stay on screen. A reply for an older query is ignored, so results never jump back to something the user has already typed past.
- **Search filters.** A scope bar (shown while searching): All, Artists, Albums or Songs; and the funnel button: a rating (Any, Love, Like, Meh, Unrated; with Use Simplified Rating off, Any, 5 Stars, 4 Stars, 3 Stars, 2 Stars, 1 Star, Unrated, each meaning exactly that many), Favorites Only, Downloaded Only (downloaded songs and albums; artists aren't downloads, so none show), and Clear Filters. While any is on, the funnel fills in and a line above the results names them (e.g. "Albums · Love · Favorites") with Clear. Changing them searches again at once. To leave enough after filtering, Search asks for 100 of each kind when a filter is on (20 normally), or 100 of the one kind chosen. Filtering uses each result's rating and favorite as the server sent them. The scope and filters are remembered on this device until cleared; a rating filter from the other rating style is turned off when the style changes, so it never hides results unseen.
- **Browsing by filter.** With nothing typed and a filter on, Search lists everything in the library that matches: artists from `getArtists`, albums from `getAlbumList2` alphabetically 500 at a time, songs from an empty `search3` (Navidrome lists every song that way; other servers may list none, and the empty message says songs can only be browsed on servers that can). Each list is kept for 30 minutes. Settings > Account > Refresh Library fetches it again at once. A scope alone, with nothing typed, still shows the genre grid.
- **Downloaded** can be filtered (the search field is always shown at the top of the list): a download matches when its name or artist, or any of its songs' titles or artists, contains the search text, ignoring case and accents. Newest download first.
- **Favorites.** Songs, albums and artists can be favorited (a heart). On the server this is Subsonic's star (`star`/`unstar`), which is what Navidrome shows as a favorite. The change shows immediately, then the server is told. If the server call fails, the heart goes back to how it was and the error is shown. A second tap on the same item while its first change is still being sent is ignored. A change made in this session wins over the flag in lists fetched earlier, so every screen agrees. The album sort Navidrome calls "starred" is shown as Favorites.
- **Ratings.** Two styles, chosen in Settings > Ratings > **Use Simplified Rating** (on by default). On: songs, albums and artists can be rated Meh 😩, Like 👌 or Love 😈 (the faces are shown beside each choice), sent with `setRating` as 1, 3 and 5 stars (Meh was 2 until 2026-10-23; ratings saved then still show as Meh, or 2 stars); ratings set elsewhere on any 1–5 scale show as the nearest level: 1–2 Meh, 3 Like, 4–5 Love. Off: they're rated 1 to 5 stars, as in Navidrome: the Rate menu shows a row of five stars across its top, filled up to the current rating, with Clear Rating below once rated; each star is a button ("3 Stars"), and tapping one closes the menu like the simplified choices do (an open menu wouldn't redraw its stars). The server always stores stars, and the app keeps the exact stars, so switching styles changes only how a rating shows (a song rated Like shows 3 stars; one given 4 stars shows Love) and nothing on the server changes until the user picks a rating. In either style, choosing the current rating again clears it (sent as 0). Song Info and Album Info name the rating in the style in use ("Love", "4 Stars"). Showing, failing and repeated taps follow the same rules as favorites.
- **Marks in song lists.** In album and playlist pages, Search, History and Downloaded, a favorited song shows a small heart and a rated song its face (😩 Meh, 👌 Like, 😈 Love), or with Use Simplified Rating off its stars as a number and a star ("4★", read as "Rated 4 Stars"), just before the duration (in History, before the time played). They follow the same session-first rule as favorites and ratings, so a change from a menu shows at once. They're display only: tapping a row still plays it, and marks are changed from the song's menu.
- **Playlists.** "Add to Playlist…" is offered for a song (its long-press menu, wherever songs are listed), an album, a playlist and an artist (their ⋯ menus and row long-presses), and a download. Now Playing's Save Queue button offers the same for the whole queue, in order, including songs already played. The sheet lists "New Playlist…" first, then only the playlists the signed-in user owns, by name (the server refuses changes to anyone else's; a playlist with no owner given is offered and the server decides). The Playlists screen's + makes an empty playlist.
  - **Adding** (`updatePlaylist` with `songIdToAdd`) appends to the end, skipping songs already in the playlist (fetched just before) and repeats within what's being added.
  - **Creating** (`createPlaylist`) keeps the songs exactly as given, repeats included, so a saved queue keeps its shape. The name is trimmed and can't be blank.
  - Song ids travel in the request URL, so at most 100 go in one request; more are sent in further `updatePlaylist` calls (a new playlist is created with the first 100, then filled). If the server doesn't return the new playlist, only a playlist of up to 100 songs can be created.
  - One change at a time. On success the sheet closes and a banner at the top says what happened for 3 seconds (e.g. "Added 8 songs to “Morning”. 2 were already there.", "All 3 songs are already in “Morning”.", "Created “Road Trip” with 40 songs."); VoiceOver announces it. On failure the sheet stays open with the server's message, so another playlist can be chosen; a chunked change may have half-completed, which the reloaded playlist shows.
- **Managing playlists.** Only the user's own playlists can be changed (the owner is the signed-in user, or the server doesn't say); anyone else's shared playlist offers none of this. All of it goes through the server, so it shows in Navidrome and other apps.
  - **Rename…, Share Playlist and Delete Playlist…** are in a playlist's long-press menu in Playlists and in its page's ⋯ menu. Rename asks for the new name (filled in, trimmed, can't be blank; an unchanged name sends nothing) and sends `updatePlaylist` with `name`. **Share Playlist** is a checkmark toggle for Navidrome's Public (`updatePlaylist` with `public`): shared, every user on the server can see and play it. Delete asks first, saying it's deleted from the server and the songs stay in the library (and, if it's downloaded, that its download is removed), then sends `deletePlaylist`; its download is removed (songs another download also holds stay), and its page closes. Each shows a banner on success ("Renamed to “Evening”.", "“Morning” is shared with everyone.", "“Morning” is no longer shared.", "Deleted “Morning”.") or "Couldn't Save Playlist" with the server's message; the Playlists list and an open playlist page reload afterwards.
  - **Removing and reordering songs** on the playlist's page: swipe a song left for **Remove from Playlist**, or choose it from the song's long-press menu, where it comes first, in its own section (at the end of that long menu it was off the screen); long-press and drag a song to move it (like the queue). Removing takes the song out of that playlist only, never from the library or other playlists. The page shows the change at once; if the server refuses, it goes back and "Couldn't Change Playlist" says why. One change at a time.
  - The API changes a playlist's songs by position: `updatePlaylist` removes songs by 0-based index (`songIndexToRemove`) and appends songs (`songIdToAdd`), removals first, in one request, so a change happens entirely or not at all. Positions, not ids, because a playlist can hold a song twice. A removal sends only the removed positions; a move (there is no move command) removes every song from the first changed position on and appends them again in the new order. Before sending, the playlist is read again; if it no longer matches the page (changed in another app), nothing is sent, the page reloads and says to try again, so the wrong song is never removed.
  - A move near the top of a long playlist lists many songs. With the server's OpenSubsonic `formPost` extension (Navidrome has it), the request is sent as a form POST with everything in the body, so its length doesn't matter; without it, a normal request is sent, and if that's too long for the server, it refuses and nothing changes.
  - A downloaded playlist follows each change (removed songs' files go unless another download uses them; moved songs keep theirs).
- **Artist page.** The artist's image (their `coverArt`, served by `getCoverArt` like album covers and cached the same way; a placeholder when there is none), their name, then the first three lines of their biography with More and Less when it is longer, then their albums. The biography comes from `getArtistInfo2` (usually Last.fm, via the server): its HTML is turned into plain text and the trailing "Read more on Last.fm" link is dropped. It loads alongside the albums but separately, so a slow or failed lookup never delays or breaks the album list; with no biography the section is simply absent. Pull to refresh reloads both. Servers using Last.fm (Navidrome does) send only Last.fm's short summary of the biography, never the whole of it, so More can't show more than that.
- **Similar Artists** (Gitea #32). At the bottom of an artist page, a **Similar Artists** section, set apart from Not Owned by a line across the top, open at first (its header shows the count and a chevron, and collapses it, like Not Owned's): a row of small round pictures with names, scrolling sideways. They come from the server's artist info (`getArtistInfo2` with `count=20` and `includeNotPresent=true`, usually Last.fm through Navidrome), in its order, including artists not in the library; with none (a server without Last.fm), there's no section. Needs no outside service and no setting. One in the library shows its picture and opens its page. One that isn't (Navidrome gives it the id `-1`) shows a placeholder, its name dimmed and an arrow on the picture (not by color alone), and opens a MusicBrainz search for the name in Safari (a link; nothing is sent until it's tapped). VoiceOver reads the name, and for one not in the library "not in your library" with the hint "Opens on MusicBrainz".
- **Albums missing tracks** (Gitea #31). With Settings > Artists > **Mark Incomplete Albums** on (the default; off, none of this is fetched or shown), on an artist page, an album the user doesn't have all of says so after its year in the album list: "9 of 12 tracks" when the full count is known, else "Missing tracks"; the album's page says so under its details line: "You have 9 of 12 tracks.", or "Some tracks are missing." when only gaps are known; tapping that line opens the album on MusicBrainz (as View on MusicBrainz does). Never a list of track numbers: gaps only show what's missing between owned tracks, so owning track 2 of 8 would list just track 1. The album's Info sheet has **View on MusicBrainz**, right under the album, above General: the release its files are tagged with, else a MusicBrainz search for its title and artist (a link the user opens in Safari; nothing is sent before). Only on those two pages: checking every album in every list would cost a server request each. Worked out after the page has loaded, never delaying it. With Look Up Artists Online on, nothing is marked until MusicBrainz has answered (or failed, leaving the gaps), so a mark appears once, with its count, rather than "Missing tracks" turning into "9 of 12 tracks" seconds later: MusicBrainz takes one request a second, so a big artist's first lookup (finding the artist, Not Owned's pages and the releases' pages) can take ten seconds or more; an artist page and an album page opened meanwhile share the one lookup, and the albums' songs are read while it runs. Then it's kept 14 days, and marks show at once. With it off, each mark shows as soon as its album's songs arrive; and kept for the session (fetched again only if an album's song count changes). Two ways to tell, both used when available:
  - **Gaps** in the owned songs' track numbers, per disc (tracks 1, 2 and 4: 3 is missing; starting at 4: 1–3 are). Always on, from the server alone (`getAlbum` for each of the artist's albums, four at a time). Blind to tracks missing from the end, and unknown when a song has no track number.
  - **The full count** from MusicBrainz, while Look Up Artists Online is on: the artist's official releases with their media (`release?artist=…&inc=media`, up to 400, kept 14 days like the rest), counting audio tracks only (a deluxe edition's DVD isn't missing songs). The album's own MusicBrainz release id (OpenSubsonic `musicBrainzId`, from Picard-tagged files) picks the exact edition; without one, the smallest edition with the same title (the same title matching as Not Owned) is used, so a standard album isn't "missing" a deluxe edition's bonus tracks. Owning more than that count (a deluxe edition) is complete. Compilations and Various Artists aren't looked up.
- **Look Up Artists Online.** Settings > Artists > **Look Up Artists Online** (off by default) adds two things to the artist page, after the server's own data has loaded (so they never delay it):
  - **A longer biography from Wikipedia**, shown in place of the server's when one is found: the opening section of the artist's article (several paragraphs, one blank line apart), in the iPhone's language when there's an article in it, else English, credited "From Wikipedia" with a link to the article (Wikipedia's text is CC BY-SA, which asks for both). The article is the one MusicBrainz links the artist to, through Wikidata (or a direct Wikipedia link on older entries), so no name is guessed at. No article, or a failed lookup: the server's biography.
  - **Not Owned**: the artist's releases the user doesn't have, from MusicBrainz, below the library's albums (headed "In Your Library" while the setting is on). Everything MusicBrainz's own site lists for the artist (official releases, no bootlegs; up to 400), in sections by kind, in this order: Albums, EPs, Singles, Live, Compilations, Soundtracks, Remixes, Other (Live, Compilation, Soundtrack and Remix go by MusicBrainz's secondary type, whatever the primary one; any other secondary type is Other). Each section starts collapsed, its header showing the kind, how many releases it holds and a chevron; tapping the header opens or closes it (open sections are remembered only while the page is open). Each section is newest first (no date last, then by title), each row the Cover Art Archive's 250-pixel front cover (a placeholder when there is none), the title and year; tapping one opens its MusicBrainz page. A release counts as owned when its title matches one of the artist's albums on the server, ignoring case, accents, punctuation and anything in brackets (so "Abbey Road (Remastered)" is "Abbey Road"; "&" is "and"). While loading, a "Looking up other releases…" row; on failure, "Couldn't reach MusicBrainz." and Try Again (a failed refresh keeps what was shown).
  - **Finding the artist:** by the MusicBrainz id the server sends for the artist (`getArtist`, else `getArtistInfo2`); with none, a MusicBrainz search for the name, taking an artist with exactly that name (ignoring case and accents) scored 90 or more, the best scored if several; none, and nothing is shown. Various Artists is never looked up.
  - **What's sent:** the artist's name or MusicBrainz id to MusicBrainz (also for their releases' track counts, see Albums missing tracks); the Wikidata item to Wikidata and the article title to Wikipedia. Never server details, credentials or listening history. MusicBrainz requests share the app's single MusicBrainz client with Look Up Songs Online, so they are at least 1.1 seconds apart in all; Wikimedia's requests carry the same contact in the User-Agent.
  - **Kept:** each answer (the artist found by name, the biography, the releases; found or not, but not failures) in `Caches/ArtistLookups` for 14 days, so opening the artist again asks nothing. It's public catalog data, shared by every account and not deleted on a switch; iOS may clear it.
- **Playing from the library.** Tapping a track plays its album or playlist from that track. Play starts at the first track; shuffle plays the same songs in a shuffled order (see Queue). Play Next (songs, albums, playlists) puts them right after the current track; Add to Queue appends them to the end. Neither interrupts playback. In search results, tapping a song plays the listed songs starting from it.
- **Random Mix** (top of Library) asks the server for 50 random songs (`getRandomSongs`) and plays them as a new queue. While it loads the button shows progress and ignores further taps; an empty result is shown under it and nothing changes. If the server can't be reached (any failure: no connection, server down, HTTP error), it plays up to 50 downloaded songs instead, shuffled, each once and only those whose files are on the device, with a note under the button saying so; the note goes away on the next mix from the server. With nothing downloaded, the error is shown and nothing changes. When the phone is online but the server doesn't answer, the fallback waits for the request to time out.
- **Carousels**, all hidden by default so Library stays simple, switched on in Edit Library (they come first, Recently Added, then Recently Played, then Spin It Back). A layout saved before keeps its own choice for Recently Added. Each is a row of album covers like Recently Added: tap one to open the album, long-press for its menu, tap the heading to collapse it (remembered). Shown carousels load when Library appears, on pull to refresh, and as soon as one is switched on.
  - **Recently Played:** albums played in the last 7 days from any app, newest first (`getAlbumList2` type `recent`, filtered by each album's last-played date; a server that doesn't give play dates shows its 15 most recent). See All opens History (Bzide's own plays).
  - **Spin It Back:** albums worth hearing again, from the whole album list (the library catalog). An album must be liked (rated Love or Like, a favorite, or played at least twice) and is never rated Meh. Its score is how much it's liked (Love 1.0, Like 0.7, otherwise 0.35; +0.4 for a favorite; up to +0.6 for plays) times its time away (played in the last 14 days 0.05; then rising from 0.3 to 1.0 at a year; never played 0.4), times a daily shuffle (0.85–1.15, the same all day). The top 15 are shown, at most two per artist. A server without plays, dates or ratings in its album list gets its most played albums, less any of the 30 most recently played.
- **Mix My Cuts** (under Random Mix; first called Shuffle Rated) plays My Cuts, shuffled, without end: songs rated Love or Like, and, with Settings > Playback > Include Favorites in My Cuts on (the default), favorites too, unless a favorite is rated Meh (the more specific verdict). Subsonic can't ask for songs by rating, so Bzide looks through the whole library: `search3` with an empty query lists every song with its rating (Navidrome supports this), 500 per page, four pages at a time, until a page comes back short. The songs found (rated or favorite) are kept for 30 minutes, so a song favorited or rated now joins within half an hour; the favorites setting applies at once; two taps at once share one look. Settings > Account > Refresh Library fetches it again at once. It plays a shuffled batch of 25 and keeps topping up like Spin Off (same engine: saved with the queue, repeat turned off, playing something else ends it), with rated songs not yet in the queue, and once all have played, a fresh shuffle of them all. Now Playing's queue heading reads "My Cuts". If My Cuts is empty: a banner says to rate or favorite songs from their long-press menu; if the server lists no songs at all (some non-Navidrome servers don't support an empty search): a banner says My Cuts can't be found on it; offline: a banner says to check the connection. While it looks, the button shows progress and ignores further taps.
- **Messages from anywhere** (a favorite or rating that didn't save, a station that wouldn't play, a big artist's confirmation, Spin Off's and Spin the Dial's banners and errors, playlist confirmations) show on whichever screen is on top: the library, Now Playing, or the visualizer or Lyrics over it, never left hidden behind a screen.
- **Layout.** Two tabs, Library (artists, albums, playlists) and Search, with a mini player above the tab bar showing the current track, play/pause and next. Tapping the mini player opens Now Playing: artwork, controls, favorite and rating, an AirPlay button, and the queue. The AirPlay button is the system output picker (AirPlay speakers and TVs, Bluetooth, the iPhone), in the theme's accent; it's there for radio stations too, which have no favorite or rating.
- **Adaptive layout (iPhone Duo and others).** Layouts follow the space the app has, never the device or screen: no screen-size, device-type or orientation checks. Now Playing is one column (cover, controls, buttons, then the queue) unless it's wider than tall and at least 700 points across (iPhone Duo's inner display, an iPhone in landscape, iPad); then the cover and controls take a left column (half the width, at least 320 points, with 20 points of room before the divider) and the queue the right, each scrolling on its own. The cover is about 72% of its column's width (280 points on a typical iPhone in portrait), at most 420 points and, in two columns, at most half the height, so the controls stay in view; covers load again at the sharper size when they grow, without going blank. The system bars are used throughout, so on iPhone Duo they move to the side where the system puts them. Known limit: on iOS 27.0 there's no way to keep the two columns off the fold of a partly folded iPhone Duo; Apple's `ArrangementView` does that from iOS 27.1 (Gitea #21).
- **Playing quality.** Now Playing's status line ("Playing", "Paused"…) shows at its right end what the current song is playing as: format and bitrate, then "Converted" if the server is transcoding it and "Downloaded" if it plays from a file, e.g. "FLAC · 1,411 kbps", "MP3 · 192 kbps · Converted", "MP3 · 128 kbps · Converted · Downloaded". It's decided with the same rule that picks the source (a download first, otherwise the current connection's streaming quality; an MP3 already at or under the cap is sent as is, so it shows as the original), and recorded when the song is loaded, so a preloaded next song shows the quality it was loaded at. The original's format and bitrate are the server's metadata. Nothing shows before a restored queue is loaded or for a radio station. Tapping the label hides it, leaving a small waveform icon; tapping that shows it again. The choice is remembered on the device.
- **Cover art** is looked up by cover art id and size (never by URL, which carries a fresh auth salt each time): memory first, then disk, then the server. Each image is fetched once however many rows show it. Fetched images are saved in `Caches/CoverArt`, which iOS may clear when space runs low. If the server can't be reached, any size of that cover already on disk is shown rather than nothing. Artwork responses never go into the shared on-disk URL cache, because their URLs carry a reusable auth token; only image responses (HTTP 200, `image/*`) are kept.

## Radio

- **Stations** are the internet radio stations saved on the server (`getInternetRadioStations`), listed by name under Library > Radio; each shows its stream's host. Stations without a usable http(s) stream address are left out. Long-press offers Play and Open Homepage (when the station has one).
- **Adding, editing and deleting stations.** Stations live in one of two places:
  - **The server** (`createInternetRadioStation`, `updateInternetRadioStation`, `deleteInternetRadioStation`), shared by every client. Navidrome allows changing them only for admins, so it's offered only when `getUser` says the user is one (`adminRole`), checked once when Radio opens; if that can't be checked, it isn't offered. A change is made on the server, then the list is fetched again; if the server refuses (error 50, not an admin) the alert says only an admin can change stations, and nothing changes.
  - **This iPhone** (My Stations), for everyone else, so anyone can keep stations whatever their server allows. Saved in a file at once, kept across launches, and part of the account's data (removed when signing in to a different account). Not synced to other devices yet.
  - **+ (Add Station)** is always there. A new station goes to the server for an admin and to this iPhone for everyone else; the form's footer says which. If the server refuses a new station (some servers don't support adding them), the alert gives the reason and offers Save on This iPhone. An edited station stays where it is.
  - **The list.** With stations in both places, the Radio list has two sections, Server and This iPhone; otherwise no headings. Edit and Delete (swipe or long-press) are on every station on this iPhone, and on server stations for an admin. Delete asks first, saying whether it's removed from this iPhone or from the server for every app. The form has a name, the stream address and an optional homepage: both addresses must start with http:// or https://, and a blank name becomes the stream's host. With no stations anywhere, the empty screen says to tap + or the magnifying glass.
- **Finding stations** (Radio > magnifying glass, Find Stations) searches Radio Browser (radio-browser.info), a free, open directory of internet radio stations. It's an outside service, so it's off until the user turns on Settings > Radio > Find Stations Online (off by default); until then the screen explains what it sends and offers Turn On.
  - **Search and filters.** The search field matches station names. A bar under it has **Country** (every country Radio Browser has working stations in, named as the phone names it, e.g. "United States" rather than Radio Browser's "The United States Of America", with station counts, most first; the phone's own country is pinned at the top; sent as the two-letter code), **Genre** (Radio Browser's 300 most common tags, most stations first, matched exactly), **Quality** (Any Quality, or 128, 192, 256 or 320 kbps or more; the button then reads e.g. "192+ kbps"; stations that don't report a bitrate, listed by Radio Browser as 0, are left out once one is chosen) and the order (**Most Played**, the default, by plays in the last day; **Top Rated**, by votes; or **Name**). Both pickers are searchable, start with Any, and are fetched when first opened (kept for the screen). Country starts worldwide. Name, filters and order combine into one search; an x clears the filters (country, genre and quality). Typing searches once it pauses for 0.4 s; any change starts again from the first page, and a newer search always replaces an older one.
  - **What's shown.** With no name, no filters and Most Played, the list is headed "Popular Now". Stations Radio Browser found broken are left out. Results come 50 at a time; reaching the end of the list loads the next 50 (a spinner while it does; if it fails, a row says why and retries when tapped), until a page comes back short. The same stream listed twice is shown once. Each row shows the name and a line like "US · MP3 128 kbps · jazz, smooth jazz" (country, format, bitrate, first three tags).
  - **Playing and adding.** Tapping plays it; Radio Browser's resolved stream address is used (playlist files and redirects already followed), else the address as entered. Each row has a + (also on long-press) that saves it with its name, stream and homepage, the same way as Add Station: "Add to Server" for an admin, "Add to My Stations" (this iPhone) for everyone else, with the same Save on This iPhone offer if the server refuses. A station saved in either place with the same stream shows a checkmark instead. Long-press also offers Play and Open Homepage.
- **What Radio Browser gets:** the search text, the chosen country code, genre and order, and the page offset; when the Country or Genre picker is first opened, a request for those lists; the stream addresses of saved stations without known details (to look up their logo, country, genres and quality), and the names of those not listed by address; and, when a station found there is played, its id (`/json/url/{id}`, which Radio Browser asks clients to send so it can rank popular stations; it counts one per station per day from the same address). The app identifies itself in its User-Agent and uses its own cookie-less session; no account, server details or anything else is sent. Radio Browser runs on mirrors that come and go, so the app fetches the list from `all.api.radio-browser.info/json/servers` (once per session), tries them in random order, moves on to the next after a network failure or server error, and keeps using the one that worked. If the list can't be fetched, `all.api.radio-browser.info` itself is asked. Failures are logged under category RadioBrowser by kind only.
- **Searching, filtering and sorting saved stations.** The Radio screen has a search field (station names) and, once there are stations, the same filter bar as Find Stations (one row above the list: Country, Genre, Quality, a clear button once any is set, and a ⇅ button for the order, whose menu checks the current one): **Country** and **Genre** (pickers listing only the countries and genres the saved stations have, with counts; your country pinned), **Quality** (128 to 320 kbps or more) and the order: **Name** (A to Z), **Country** (by country name), **Quality** (highest bitrate first) or **Date Added** (newest first); stations missing what's sorted by go last, by name. The Server and This iPhone sections are each filtered and sorted. The filters and order are remembered on this device (the search text isn't); the x clears the filters. With nothing matching: "No Matching Stations", explaining where country, genre and quality come from. Each row shows what's known (e.g. "US · MP3 128 kbps · jazz, smooth jazz"), else the stream's host.
- **Station details** (country, genres, format and bitrate, and the logo) aren't kept by the server, whose stations have only a name and addresses. They come from Radio Browser: a station added from Find Stations keeps the details it had there; while Find Stations Online is on, opening Radio looks up each station with none known yet by its stream address (`/json/stations/byurl`, one at a time; the listing with a usable logo, filled in from the others). **Not listed by address** (Radio Browser may only have an older one): by the station's name instead (`/json/stations/search`, up to 50, broken listings included, since a dead old address still has the station's details), keeping only listings named exactly the same (ignoring case, accents and extra spaces), and only if they agree on the website (ignoring `www.`) and the country, so they're one station listed more than once; two stations sharing a name, or several with neither a website nor a country, count as not listed. "Not listed" is remembered, so each station is asked about once (stations remembered as not listed before the name search existed are asked once more); a failed lookup is tried again next time. Stations without details (hand-added ones Radio Browser doesn't list, or with lookups off) drop out while a country, genre or quality filter is on. Details are remembered by stream address (so editing a station's stream looks it up again) and kept with the account's data; logos remembered before details existed carry over, and those stations are looked up once more for the rest.
- **Date added** isn't given by the server either, so Bzide records when it first lists each station (by id), kept with the account's data on this device: for stations added in Bzide, when they were added; for stations already on the server, when Bzide first saw them (all at once, the first time Radio is opened after this feature arrived).
- **Logos.** A station shows its logo in the Radio list, Find Stations, the mini player, Now Playing and on the lock screen; without one, the radio symbol (and the usual placeholder in Now Playing). Logos come from Radio Browser and are loaded from the stations' own websites, never from the server: they come with the station's details (above), and are cached like cover art. Only https logos load (the App Transport Security exception covers audio only): an http logo is tried over https, and if the site doesn't serve it there, the station shows the symbol. Logos are scaled down to the size shown.
- **Playing a station** replaces the queue with that one station, like playing a new album. A second tap while one is starting is ignored.
- **Stream address.** A direct stream or an HLS (`.m3u8`) address goes to the player as is. A `.pls` or `.m3u` playlist file is read first and its first stream is played (`.pls`: the lowest-numbered `File` entry; `.m3u`: the first line that isn't blank or a `#` comment). Plain http streams play (the app's only App Transport Security exception, for audio); a playlist *file* on plain http can't be read, and the app says to use the station's direct stream address instead. If the file can't be fetched or lists no stream, the error says so ("Couldn't Play Station").
- **A station is live:** no duration or progress bar ("Live" instead), no seeking, previous disabled, nothing preloaded after it. Now Playing hides what doesn't apply to a station: shuffle and repeat, the heart and rating, Lyrics, Visualizer, the … menu (Spin Off, Song Info, Save Queue) and the sleep timer's End of Song. It's never scrobbled or added to play history, can't be favorited, rated or added to a playlist, and isn't offered to Siri. The lock screen marks it as a live stream with scrubbing and previous disabled.
- **Pause and resume** rejoins the broadcast live rather than continuing minutes behind. If the stream ends or fails while listening, it's retried like a failed song (same delays and network-return retry), always from "now".
- **What's on.** When the stream announces what it's playing (Shoutcast/Icecast `StreamTitle`, or a title in its metadata), that becomes the title in the mini player, Now Playing and on the lock screen, with the station's name beneath; otherwise the station's name is the title. A new track or station clears it.
- **Station Info** (Now Playing's info button while a station plays, in place of the … menu, and Station Info in a saved station's long-press menu in Radio) shows everything known about the station, in sections left out when empty: **On Air** (the announced song); **Station** (the stream's own description, country, region, languages, genres, homepage); **Stream** (format, bitrate, sample rate, address, server); **Radio Browser** (votes, plays today, whether its last check found the station working), when listed there; **In Bzide** (saved on the server or this iPhone, or not saved; when it was added, or first played for an unsaved one). What Bzide knows shows at once; then, together, Radio Browser's listing by stream address, else by exact name as for Station details (with Find Stations Online on) and the stream's response headers (`icy-description`, `icy-genre`, `icy-br`, `ice-audio-info`, `icy-url`, `Content-Type`, `Server`), read from the address being played and then disconnected. Headers are read only from https streams: the App Transport Security exception covers audio playback, not other requests. Radio Browser's listing wins over what Bzide knew; the headers fill in what's still missing. For the station playing, the station is the saved one with its id (or, for a dialed one, its stream), else the station the dial tuned to, else what the playing entry kept.
- **Song Info for the song on air.** While a station plays, Now Playing's info button is a menu: Station Info, and Song Info (when the station names a song). Song Info opens the library's own Song Info if the song is in the library (see In Your Library); otherwise, with Settings > Radio > **Look Up Songs Online** on (off by default), what MusicBrainz has (title, artist, the album, year, length, and its MusicBrainz page), else just the title and artist the station gave. With it on, each announced song is looked up once on MusicBrainz (the artist and title only; remembered for the session, found or not; failures retried): among official studio albums first, taking the earliest (so a live bootleg or a compilation doesn't win), else the best match on any release, preferring official ones; a recording counts only if its title and artist match the announced ones and MusicBrainz scores it 80 or more. Requests name the app and a contact (Info.plist `MusicBrainzContact`) and are at least 1.1 seconds apart; when MusicBrainz is busy (HTTP 503) a request is tried again after 2 seconds, up to twice. **The artwork** for a station (Now Playing, the mini player, the lock screen and Control Center) is the cover of the song on air: the library's own cover when the song is in the library (no outside service), else, with Look Up Songs Online on, the album's front cover from the Cover Art Archive when it has one (checked there, a 500-pixel version, over https), else the station's logo. The on-air song is followed whether or not any screen is open (with the app in the background too): each new station, announced title, or change to Look Up Songs Online looks it up again, and a new entry clears the cover at once.
- **In Your Library.** When a station announces a song that's in the library, Now Playing shows an "In Your Library" badge under the controls; tapping it offers **Play It Now** (your copy, in place of the station) and **Go to Album** (opened within Now Playing). Shoutcast and Icecast stations announce "Artist - Title" in one field (`StreamTitle`); HLS stations (`.m3u8`) usually send ID3 tags with the title and artist separately, which are joined as "Artist - Title" (just the title if it already names the artist). The announced title is read as "Artist - Title" (also with – or —; the first dash splits) or "Title by Artist"; a title that's just the station's name, or looks like an ad, jingle or web address, isn't a song. Each new title searches the user's server only (`search3`: artist and title, then the title, then the artist), and a song matches when its title is the same (version notes like "(Remastered)" aside, accents, case and punctuation ignored) and its artist is the same or names the other ("feat." and duos); titles announced the other way round match too. Each title's answer is kept for the session; a failed search isn't, and a newer title replaces a slower search. Stations that announce nothing get no badge.
- **Wishlist** (Gitea #33; called Tagged Radio Songs until then; the saved list carries over, its entries as Found on Radio). Things to remember, and maybe get, in sections, in this order and only those with something in them: **Found on Radio**, **Missing Songs**, **Albums**, **Artists**. Library > **Wishlist** lists each section newest first.
  - **Found on Radio:** when the search says a song on air isn't in the library, Now Playing shows **Tag Song** under the controls instead of the badge (nothing while the search runs); once tagged, "Tagged" with a checkmark. An entry keeps the artist and title (MusicBrainz's spelling, album, year, cover and page too, when Look Up Songs Online found them), the station's name and the date; shown with its cover (else a placeholder), title, artist, and "Heard on <station> · <date> · <album>".
  - **Missing Songs:** an album page's ••• menu has **Add Missing Songs to Wishlist** when the album is marked incomplete and Look Up Artists Online is on (MusicBrainz is the only source of the songs' titles). It reads the album's release on MusicBrainz (the one its files are tagged with, else the smallest edition with that title, as the count does; `release/<id>?inc=recordings`, audio media only, kept 14 days) and adds, in the release's order, each track whose title isn't one of the album's songs (titles compared ignoring case, accents, punctuation and anything in brackets), with the album, year, the release's cover and its MusicBrainz page. A banner says how many ("Added 7 songs to your Wishlist.", or "Those songs are already on your Wishlist."), or that MusicBrainz couldn't be reached. Shown as "From <album> · <date>".
  - **Albums:** long-press a release under Not Owned > **Add to Wishlist** (or "On Your Wishlist", disabled, if it's there). Keeps the title, the artist, year, cover and MusicBrainz page; shown as "<year> · <date>".
  - **Artists:** long-press a Similar Artists picture with the arrow (not in the library) > **Add to Wishlist** (or "On Your Wishlist"). Keeps the name and a MusicBrainz search for it; shown with a round placeholder.
  - **Never twice:** a song (from the radio or an album, matched as for In Your Library), an album (title matched as Not Owned's, and artist) or an artist (by name, ignoring case and accents) already on the list isn't added again.
  - **Found in your library:** launching the app, opening the list, or pulling down searches the user's server for each entry not yet found (one check at a time): a song by artist and title, then the title, then the artist; an album by its title (matching title and artist among the albums); an artist by name. One found is marked with a house symbol, and tapping it plays the song or opens the album or artist; the day it was first found is saved (cleared if a later search no longer finds it, so the count starts again). Entries stay until removed, unless Settings > Wishlist > **Remove Found Items** is on (off by default): then entries found in the library are removed **Immediately**, **After 7 Days** (default) or **After 30 Days**, counted from the day found; checked after each search and whenever the setting changes.
  - To remove one yourself: swipe, or long-press for Play (a found song), Copy (Artist and Title, Artist and Album, or the Name), Open MusicBrainz Page (if known), Buy and Remove.
  - **Buy** (Gitea #29): a submenu of stores that sell downloads, each opening its search for the entry in Safari or the store's app: **Apple Music** (`music.apple.com/search`, which picks the country itself), **Bandcamp** (tracks, albums or artists, by kind), **Qobuz** and **Amazon** (digital music), the last two in the iPhone's region's store, else the US store. It searches for the artist and title, an album's artist and title, or an artist's name. Links only, opened by the user; nothing is sent until one is tapped.
  - **Share** (the toolbar, when the list isn't empty): **Share as Text**, the list by section, "- Artist - Title" per line (an artist's name alone), with "(heard on <station>)", "(from <album>)" or "(<year>)"; or **Share as CSV**, a `Wishlist.csv` file with the columns Kind, Artist, Title, Album, Year, Station, Added (the date) and MusicBrainz, quoted where needed, for a spreadsheet or a script (e.g. one that hands the list to a download tool, outside Bzide). Through the iOS share sheet; Bzide itself sends it nowhere.
  - Kept on this iPhone only, in `Application Support/Wishlist.json`; each account has its own list (see Account), never sent to the server or anywhere else; each client keeps its own. (#29 may later send entries to slskd; the artist, title and album kept here are what it would need.)
- **Relaunch:** a station that was playing comes back paused, and play rejoins it live.

## Spin the Dial

- **Spin the Dial** (Library, below Mix My Cuts, shown by default and hidden or moved in Edit Library like the others) finds a radio station on Radio Browser and plays it. It uses Find Stations Online: with that off, tapping it explains and offers Turn On and Spin.
- **How it picks:** it picks a genre at random, weighted by the taste it works from but flattened a little (weights to the power 0.6) so the long tail comes up too; asks Radio Browser for working stations whose tags contain that genre ("rock" finds "classic rock"), best voted first, within the restrictions; leaves out the last 30 stations it dialed; and plays one of the top 40 left at random. A genre with nothing tries up to 3 others, then any genre (unless genres are chosen in Settings). Only the genre and restrictions go to Radio Browser, never listening history. The play counts toward the station's popularity, as in Find Stations.
- **Modes** (Settings > Spin the Dial > Mode): **My Taste** (the default): genres from play history (a play's weight halves every 30 days) and favorites (half a play each), from each song's genre tag split into Radio Browser tags ("Hip-Hop/Rap; R&B" becomes "hip hop", "rap", "r&b"); with no history or genres, My Library, then any genre. **My Library:** genres from the library (getGenres), weighted by songs (else albums). **Surprise Me:** any working station, in Radio Browser's random order. **Something New:** popular Radio Browser genres (top 300 tags, leaving out non-genres like news, talk, hits) that the listening and library don't cover (a related genre counts as covered), and only stations not saved (server or this iPhone) and never dialed.
- **Settings > Spin the Dial** sits right below Radio (Find Stations Online), since it uses Radio Browser; with Find Stations Online off, its controls are disabled and its footer says to turn that on.
- **Restrictions** (Settings, with any mode): **My Country Only** (the phone's region), **Genres** (any number, from Radio Browser's most common genres, searchable; in My Taste and My Library the dial weights within them; none chosen means any), **Minimum Quality** (Any, or 128 to 320 kbps). With restrictions and nothing found: "Couldn't find a station with these settings. Try fewer restrictions in Settings > Spin the Dial." Errors show as a Spin the Dial alert on whichever screen is on top (so Next on a dialed station in Now Playing shows it there).
- **While it plays:** a banner names it ("Tuned to WWOZ · jazz · US") for 4 seconds. Next (in Now Playing, the visualizer and on the lock screen) spins again with the same settings; for other stations Next stays off. Now Playing shows **Save Station** under the controls while a dialed station plays that isn't saved yet (no saved station, on the server or this iPhone, has its stream address). It saves it as + in Radio does (to the server for an admin, else to this iPhone; if the server refuses, it offers Save on This iPhone), with what the dial found: name, homepage, logo, country, genres and quality. If the app was relaunched since the dial tuned to it, it saves what the playing entry kept (name, stream and logo); Radio looks up the rest. The button then reads "Saved"; a dialed station already saved reads "In Your Stations" instead (shown once the saved stations have loaded). The dialed stations (up to 500, by Radio Browser id) are kept with the account's data. Radio plays aren't in play history, so the dial never feeds on itself.

## Siri

- **What Siri knows.** Songs, albums, artists and playlists are Siri entities using the system's audio schemas (ids are the server's). Every artist, album, playlist, song, download and queue row is annotated with its entity, as are the album, artist and playlist page headers; Now Playing publishes the current song. So "Ask Siri" from a long-press, or "play this" / "add this to …" while looking at something, refers to that item. iOS 27 adds Ask Siri to menus on its own; the app can't remove it (see `docs/ISSUES.md`).
- **Finding things by name.** Siri looks entities up by id (`getArtist`, `getAlbum`, `getPlaylist`, `getSong`; ids the server no longer has are skipped) or by name (`search3`, 10 of each kind; playlists by filtering the user's list, since the server has no playlist search). For "play X", an exact (case- and accent-insensitive) name match comes first, then songs, albums, artists and playlists.
- **"Play … in Bzide" (audio search).** On iOS 27, a spoken play request reaches the app's audio search (an `IntentValueQuery` over `MediaIntents.AudioSearch`); if its answer is empty, fails or is slow, Siri plays from Apple Music instead, without saying why (Gitea #34). So it answers fast and with something whenever it can:
  - **Something named** ("play Creed in Bzide"): the search and the playlist-name match run at the same time; the playlist list is kept for 10 minutes rather than fetched each time; and after 4 seconds the answer is whatever has arrived (the playlists, if the search is still out). "Play Random Mix in Bzide" starts a Random Mix.
  - **Nothing named**: it carries on with the queue (the current song is offered, and playing it resumes rather than replacing the queue), or starts a Random Mix if nothing is queued. Siri doesn't send "play music in Bzide" here, though: without a phrase of its own it answered that Bzide doesn't support that. So the **Play Music** App Shortcut does the same for the exact phrases "Play music in Bzide", "Play my music in Bzide", "Play Bzide", "Resume Bzide" and "Start Bzide" (it also appears in the Shortcuts app).
  - A web address finds nothing (no Navidrome item has one).
  - **The app's name heard as music.** "Bzide" is said "Bee-zide" (or "Bee-side"), and Siri sometimes hears it as part of the request: on device it wrote "Bzside", searched Bzide for that, found nothing and played a song by an artist called Bzside from Apple Music. So the words Siri sends lose a leading or trailing app name or mishearing of it ("in Bzside", "on B-side", "bee zide"), and what's left is searched; if that's nothing or generic ("music", "my music", "some music", "songs", "something"…), it's treated as nothing named. The app's Info.plist also gives Siri `INAlternativeAppNames` (Bee-zide, Bee-side, Bzside, with "sounds like" hints) to hear the name as the app. Debug builds (installed from Xcode) log the words Siri sent in the clear, to see what it heard.
  - Each answer is logged (category Siri: what kind of request, how many results, how long it took; the spoken words only as private data), to diagnose a request that went to Apple Music.
- **Play** (`playAudio` schema): plays the item as the long-press Play does (an artist's albums oldest first). Shuffle plays it shuffled; Repeat also turns on repeat all; "next" and "last" put it after the current song or at the end of the queue instead of replacing it.
- **Add to Playlist** (`addToPlaylist` schema): adds the item to the named playlist with the same rules as the sheet (only new songs; long lists chunked). Siri says the result, e.g. "Added 8 songs to “Morning”. 2 were already there."; a failure is spoken as the server's message.
- An artist with more than 100 songs asks for confirmation first, as the menus do.
- **Favorite Current Song / Unfavorite Current Song**: hearts (or un-hearts) the song playing now on the server, as Now Playing's heart does. It sets rather than flips, so pressing it twice (from the Action button, a Shortcut or the lock screen control) can't undo it; already a favorite counts as done and isn't sent again. Siri says the result ("Added "Dawn" to your favorites."). Nothing playing: "Nothing is playing in Bzide."; a radio station: "A radio station can't be a favorite."; a failed request: the server's reason. Phrases work without setup ("Favorite this song in Bzide", "Favorite this in Bzide", "Add this song to my favorites in Bzide", "Unfavorite this song in Bzide", "Remove this song from my favorites in Bzide"); both also appear in Shortcuts and for the Action button. They run in the app's process (audio playback intents), where the queue and server connection are.
- **No system like command.** Bzide leaves `MPRemoteCommandCenter`'s like and dislike commands off. iOS draws liking as a star on the Lock Screen and in Control Center, and in Bzide a star means a rating, not a favorite (Gitea #14). So Siri's "favorite this song" or "like this song" said without "in Bzide" isn't handled by Bzide; "Favorite this song in Bzide" is. Favorites are set with Now Playing's heart, the Now Playing and Shortcuts widgets, the Favorite Song control and the Siri phrases above.

## Widgets

- **What the app shares.** The widgets and controls (in the BzideControls extension) run in their own process and can't see the engine. The app writes what they show into the App Group's folder (`group.com.erichebert.musicapp`): `NowPlaying.json` (title, subtitle, playing or not, a station or not, whether there's a next, whether the song is a favorite, and which cover the artwork is of) and `NowPlayingArtwork.jpg` (the cover, at most 400 pixels on its longest side). Nothing else: no server address, credentials or listening history, so the extension never talks to the server. The title and subtitle are what Now Playing shows (for a station: the announced song and the station's name, else the station's name). "Playing" includes buffering and reconnecting, so the button shows pause while music is on its way.
- **When it's written.** On launch (with the restored queue, paused), and whenever the song, its title, playing or paused, next, the favorite or the cover changes; each write asks WidgetKit to reload the Now Playing widget and the Favorite Song control, at most once a second (a run of changes reloads once more at the end). A new cover is saved before the snapshot names it, so a widget never shows the last song's cover with this one's title; until it's saved (or if it can't be had), a placeholder. Artwork left from before is dropped at launch and saved again. With nothing queued, both files are removed; signing out removes them too, so the widget never shows the last account's song. When the app is quitting, the snapshot is marked paused (the music stops with it).
- **Now Playing widget** (Home Screen small and medium, Lock Screen rectangular): **small**: the cover, play/pause, the title (two lines) and subtitle; **medium**: the cover, the title and subtitle, and previous (not for a station), play/pause, next (dimmed when there's none) and the heart (filled when a favorite; not for a station), which favorites or unfavorites it; **Lock Screen**: the title and subtitle on a line each, and play/pause. Nothing queued: "Not Playing" and "Open Bzide to play something." The buttons do what the lock screen's do (previous restarts the song after its first seconds, as there), through audio playback intents the system runs in the app, starting it in the background if need be (the restored queue plays). Tapping elsewhere opens the app (`bzide://now-playing`), with Now Playing open when something's queued.
- **Shortcuts widget** (Home Screen small and medium): four buttons in a grid that start music without opening the app, as the Home Screen quick actions do. **Continue** plays the queue from where it was (on the medium size, it names what it continues, "Title · Artist", or says "Playing"); dimmed with nothing queued or while playing. **Random Mix** and **Mix My Cuts** start those mixes. **Favorite** favorites the playing song, or with the song a favorite already (a filled heart) unfavorites it; dimmed with nothing playing or a station. Small: an icon and a short label each; medium: the label beside the icon. It reads the same snapshot as the Now Playing widget and is reloaded with it. The buttons are audio playback intents run in the app (starting it in the background if need be), which waits until the mix has started.
- **Themes.** The Now Playing and Shortcuts widgets draw in the app's theme. The app shares the theme in the App Group (`Theme.json`: the theme's background, tile and text colors, and the accent as it looks in light and dark mode; colors only), when it or the accent changes and at launch, and asks both widgets to redraw. With a theme (Catppuccin, Gruvbox, Nord, Dracula, Tokyo Night): its background, its text (secondary text a step dimmer), its tile color (a shade darker than the background in light themes, lighter in dark ones), and the accent on the buttons (play/pause, previous, next, the heart, the Shortcuts icons). With System, Light or Dark: iOS's own widget look in the phone's mode, with the system accent (Bzide Red by default) in its light or dark shade. Only in full color: on the Lock Screen and in the Home Screen's tinted and clear modes, iOS draws the widgets in its own style. The Favorite Song control is drawn by iOS.

## Play history

- A play is added to the history at the moment it counts for scrobbling (half the track or 4 minutes, whichever comes first), recorded with the song as it was and the time the play started. Skipped plays aren't recorded. Works offline.
- Kept on this device only, in `Application Support/PlayHistory.json`; the Subsonic API has no list of plays to sync with. Each client (iOS, later web and Android) keeps its own.
- Shown newest first, grouped by day (Today, Yesterday, then dates).
- Repeat plays are combined by default: within a day, a song appears once, at the time of its latest play that day, with its number of plays that day ("3 plays") when more than one. Only plays that match the current filters are counted. "Show Every Play" in the filter menu lists each play separately; the choice is remembered.
- Filters combine: text matching the track, artist or album (ignoring case and accents), and a period: Today, Last 7 Days, Last 30 Days, All (the default), or a custom range of whole days, in either order.
- Tapping a play plays just that song. Long-press offers Play Next, Add to Queue, Favorite and Rate.
- Retention: 7 days, 30 days (default), 90 days, 1 year, or forever. Older plays are dropped at launch, on every new play, and when the setting changes. Clear History removes everything, after confirmation.

## Caching and offline

### Streaming quality

- The user picks a quality for Wi-Fi and one for cellular: Original, or 320, 256, 192, 128 or 96 kbps. Defaults: Original on Wi-Fi, 192 kbps on cellular.
- "Cellular" means any connection iOS marks as expensive (cellular, a personal hotspot) or constrained (Low Data Mode).
- Original streams the file as stored. Any bitrate asks the server to transcode to MP3 at that bitrate (`maxBitRate`, `format=mp3`); the server may send the original when it is already at or below that.
- The quality is chosen each time a track is loaded. A change of network or setting applies from the next track loaded; a track already playing, or already buffered as the next one, keeps its quality.
- A downloaded song always plays from its file, whatever the connection.
- Settings are saved on the device (not secret). Saved settings that can't be read fall back to the defaults; a setting missing from what was saved (added in a later version) takes its default and the others are kept.

### Downloads

- The user downloads a whole album or playlist. Its song list is saved as it was at that moment, so it can be listed and played with no server. Downloading it again updates the list: new songs are fetched, songs no longer in it are dropped.
- **Downloaded playlists stay up to date.** A playlist can change after it's downloaded (in Bzide or another app), so Bzide checks: every downloaded playlist when the app comes to the foreground (at most every 15 minutes, after a check that reached the server), a playlist whenever its page is opened online, and right after songs are added to it in Bzide. A change (songs added, removed or reordered, a new name or cover) updates the download as downloading it again would: new songs download under the usual quality and cellular rules, removed songs' files go unless another download uses them, and the download keeps its place in the list. Offline nothing changes, and the foreground check runs again on the next return to the app. A playlist the server says no longer exists keeps its download until the user removes it. Albums aren't checked.
- **Single songs.** A song's long-press menu offers Download, which downloads that one song as its own download (`song:<id>`), with the same quality, cellular, ordering and storage rules. Once downloaded it offers Remove Download. A song that's only on the phone as part of a downloaded album or playlist shows a grayed-out "Downloaded" instead: it's removed with them. Library > Downloaded lists songs downloaded on their own as one "Downloaded Songs" row at the top (with their count and progress; its long-press plays or queues them all), which opens the list, newest first. The Downloaded search matches them by title and artist too.
- **Download quality** (Settings > Downloads, Original by default, same choices as streaming quality). At Original, songs are downloaded in their original format (`download` endpoint, never transcoded). Below it, they're fetched from `stream` with that `maxBitRate` and `format=mp3`, so the server converts them as they download; the size isn't known in advance, so such a song shows as downloading without a percentage until it's done. The quality is fixed for each song when its download starts and saved with the download index, so changing the setting mid-download, or a relaunch before a converted song finishes, never mislabels a file. Songs already downloaded are kept as they are: a change applies to songs downloaded afterwards.
- Files go to `Application Support/Downloads/Files/<song id>.<extension>`, excluded from iCloud backup. A converted song is `.mp3`; an original takes the extension from the song's metadata, else from the server's file name.
- Each song is stored once, however many downloaded albums or playlists contain it. Removing an album or playlist deletes only files no other download still uses, and stops their running downloads.
- Three songs download at a time; the rest wait in the order the user asked for them (oldest download first, album order within). Downloads run in a background `URLSession`, so they carry on while the app is suspended or terminated. On the next launch the app reconnects to them, restarts whatever was waiting, and cancels system downloads nothing wants any more.
- A failed song stays failed until the user retries; after a relaunch, failed songs are tried again. A response that isn't 2xx, or is JSON/XML (how Subsonic reports errors, even with HTTP 200), is a failure, never saved as a song.
- "Download over cellular" is off by default: downloads then wait for Wi-Fi. The setting applies to downloads started after changing it.
- Any song with a downloaded file plays from it, on any connection and with the server unreachable. If the file has gone missing, the song streams instead.
- Downloaded albums and playlists keep their covers offline: the collection's cover and every song's cover (they can differ, e.g. compilations) are stored once each at 900 px in `Downloads/CoverArt`, and serve every size. A cover no remaining download uses is deleted. Covers that couldn't be fetched are retried when downloads change and at launch.
- No storage limit; the user removes downloads, one at a time or all at once in Settings, which also shows the space used.
- The download URL carries an auth token and is handed to iOS's download service. Subsonic has no other way to authenticate a download.

## Accessibility

Checked against the App Store's Accessibility Nutrition Labels (Gitea #19).

- **VoiceOver and Voice Control:** every control has a spoken name (icon buttons use titled labels; color swatches say their name and whether they're chosen). Banners are announced. Headings are marked as headings; decorative images are hidden. The progress bar reads the time ("0:05 of 3:36") and a swipe up or down on it seeks 15 seconds forward or back. Each line of synced lyrics is a button ("Jumps the song to this line"); instrumental breaks are skipped.
- **Larger Text:** screens use the system text styles, so they follow the text size. Lyrics are sized relative to it too (from 26 and 30 points at the default size). At the accessibility text sizes, a Library row's See All goes under its title (which wraps left-aligned) rather than squeezing it into a narrow column, Now Playing's Clear Up Next goes under the Queue heading, and Library's Random Mix, Mix My Cuts and Spin the Dial wrap beside their icons. Controls grow with the text only up to the largest standard size (not the extra accessibility sizes), where they still fit and match: Now Playing's transport controls and icon row, and the mini player, whose space is fixed.
- **Reduce Motion:** lyrics move to the current line without the spring, lines don't shrink or animate, and an instrumental break's dots don't breathe. The visualizer, being all motion, shows "Reduce Motion Is On" with a **Start Anyway** button instead of starting by itself (each time it's opened).
- **Visualizer setting:** Settings > Visualizer > **Visualizer** (on by default). Off, Now Playing has no visualizer button, so no visualization can be opened at all.
- **Increase Contrast:** lyric lines that aren't current are brighter (60% instead of 35%) and never blurred; the lyrics' notes and credit are brighter too.
- **Not by color alone:** favorites and ratings change shape when set (filled heart and star), the playing song in the queue has a speaker icon, and "Wrong lyrics?" changes its icon (a checkmark) as well as its color when a chosen version shows.
- **Dark interface:** light and dark modes and the dark themes. Captions and audio descriptions don't apply (no video).
