- [fixed] 2026-10-13: A few songs got LRCLIB lyrics for a different recording, running a couple of lines behind the vocals throughout; most songs, and tapping lines to seek, are timed well. - [fixed] 2026-10-15: The No Lyrics note sometimes says "LRCLIB couldn't be reached to look further." on songs where LRCLIB probably isn't down. Any error from the lookup counts as unreachable. Likely cause: leaving the lyrics screen while LRCLIB is still being searched (up to three requests in a row, and the search can take a few seconds) cancels the request; the cancellation is treated as a connection failure, and because the server did answer, the result is cached as "No Lyrics" for the rest of the session, so reopening the screen shows the same note without asking again. Other possible causes, which the app can't tell apart yet: a real network error or timeout, LRCLIB returning an error (busy or rate-limited, 5xx or 429), or a reply that doesn't decode. Fix: ignore a canceled lookup (don't show or cache it), don't cache a failed online lookup so reopening tries again, and log the error's kind (redacted: no song details) under category LRCLIB. (Lyrics, No Lyrics note) Fixed 2026-10-15 as proposed: a canceled lookup is dropped, a result where the server or LRCLIB failed isn't kept, and LRCLIB failures are logged by kind (URLError code, HTTP status, or unreadable reply). If the note still appears, the Console lines (`subsystem:MusicApp category:LRCLIB`) show which kind.
- [fixed] 2026-10-15: Adding a station found on Radio Browser failed with "Server error 0: invalid semicolon separator in query" when its stream address contained a `;` (common in Shoutcast addresses, e.g. `http://host:8000/;`). - [idea, later; Gitea #10] 2026-10-15: Apple WeatherKit for Weather (Live), once the paid developer account is set up.
